# StudyKit 主动用户改版简报

来源：John M. Carroll & Mary Beth Rosson, Paradox of the Active User（Interfacing Thought, MIT Press, 1987）。
配合 stageshow skill 的 faux UI 规范：少而真、一个焦点、一个动作、每个动效有原因。

## 论文给产品的 6 条硬约束

1. 用户是来完成任务，不是来学产品。首次打开不做强制教程/多步设置，直接给一个 30 秒可完成的小任务。
2. Production Paradox：先做，后懂。用 guided exploration cards（引导探索卡）把“学习系统”伪装成“完成今天的事”；每张卡只做一件事，有即时结果。
3. 风险要可逆。每个会改变数据的动作都要有撤销/返回；错误只提示、不惩罚、不把用户困在死路。
4. 渐进披露。首屏只放 2-3 个主行动，其他能力收进“更多”；高级参数不挡在第一次使用前面。
5. Assimilation Paradox：用熟悉的隐喻，但别骗人。“签到日历=纸质打卡表”“单词卡=抽认卡”“小测=三题一页”；不要放“题库/拍照识别”这种点进去没功能的假入口。
6. 系统模型可见。用一句人话解释本地存储、复习为什么出现、签到/补签规则；不要靠说明书。

## 产品主张

“不用设置，先做一件小事。”
首页第一屏给一张「今天从哪开始」卡，三步各 30-90 秒：

1. 签到打卡（1 秒）
2. 复习 5 个词（2 分钟）
3. 做 3 道小测（1 分钟）

三步完成显示「今日已起飞 3/3」，并给下一步建议。卡上直接可做，不跳教程。

## HarmonyOS 版（重点，审核被指“功能未完善”）

当前问题：24 个示例词、首页“0/2”硬编码、今日待复习 0 硬编码、“题库练习/拍照识别”是死入口、Profile 明说“后续接入/MVP”。必须做成真实可用：

### 必须实现
- 真实词库：至少 60 个常用词（word/phonetic/meaning/example），替换“示例词”表述。
- 真实复习排期：本地 SRS（Leitner 5 盒即可），记录每个词的 box、dueDate、lastReviewed、correct/wrong；今日待复习按到期计算；“记住了/再学一次”更新排期；可撤销上一次。
- 真实小测：从词库生成 4 选 1（至少 5 题/组），作答后立刻反馈、显示正确答案与例句；结果落库（今日是否完成、正确数、错题）。错题进入“错题”列表，可重练。
- 今日任务卡：根据真实数据算 0/3（签到、复习 5 词、小测 3 题）；每项可点、有完成态；全部完成显示鼓励与下一步。
- 学习报告：已掌握、待复习、正确率、连续学习天数、累计学习天数；本地数据可重置（二次确认）。
- 帮助/可逆：单词页有“撤销上一步”；签到补签可撤销；删除“后续接入/MVP/示例”这类未完成文案；不再有死入口。
- 导航：学习 / 签到 / 单词 / 练习（小测+错题）/ 我的，共 5 tab；平板和手机都可用。
- 保持暖纸感主题、ArkTS/ArkUI 原生，不改包名/签名配置。

## Android 版（已有完整功能，补主动用户入口）

- 在首页 hero 上方加一张「今天从哪开始」的 3 步引导卡（可完成后收起；每日重置；不要强制 onboarding）。
  1. 签到：接现有签到状态/动作；
  2. 复习：接现有单词入口，显示今日已复习/待复习；
  3. 小测：接现有题库练习入口，显示今日是否已练。
- 加一个轻量“为什么这样安排”/帮助 bottom sheet：本地优先、可撤销、无账号；不要长篇教程。
- 把首屏已有的“模考/错题本/待校对”收进“更多学习方式”折叠区（渐进披露），保留“题库练习”主入口。
- 不删除既有功能；不改包名、签名、版本策略；构建通过。
- 验收：gradlew assembleDebug 成功；首页截图；3 步卡可完成/重置。

## stageshow 用图

输出 2 张 900x1100 左右的手机界面静帧（安卓/鸿蒙同构）：
1. 首页「今天从哪开始 0/3」+ 可点的三张任务行；
2. 完成后「今日已起飞 3/3」+ 单词复习/小测的成果。
用暖纸色（#F7F2E8 / #FBF7EF）、墨色文字、金/绿两个状态色；真实中文文案，不用灰条。
