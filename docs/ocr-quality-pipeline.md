# OCR 质量与结构化管线（v3.7）

> 本文记录 v3.7 在「拍照/相册录题」这条链路上做的事、阈值口径与没做的事。
> 目标只有一个：**不要让错误内容静默进入 FSRS 复习**。

## 1. 链路

~~~
相册/相机
  → BitmapFactory 采样解码（长边 ≤ 2048） + EXIF 转正
  → 质量体检：模糊 / 偏暗 / 过曝 / 反光 / 明显倾斜          （PhotoQualityAnalyzer，640 长边）
  → 投影法摆正：±12° 内估计，|角| ≥ 1° 才反向旋转            （Deskew，480 长边）
  → PP-OCRv6 det → rec（逐行）
  → 低置信度行二次识别：扩边 12% + 放大 1.6~2x，最多 8 行      （PpOcrOnnxEngine.recognizeWithRetry）
  → OcrReport：逐行分数 / 质量 / 摆正角 / 重试行数
  → 导入解析（一题一行）→ 预览
  → 低置信度行默认剔除（可逐行勾回） + 顶部提示
~~~

整条链路只依赖本地图像统计与已有的两个 ONNX 模型：**不联网、不加模型、不加 OpenCV**。
解码/体检/摆正/推理都在 Dispatchers.IO，协程取消时向上抛 CancellationException。

## 2. 质量门控

| 问题 | 判据（640 长边灰度） | 说明 |
| --- | --- | --- |
| 模糊 | 拉普拉斯方差 < 42 | 文字页通常 100+；失焦/手抖常 10~30 |
| 偏暗 | 均值 < 55 且对比度 < 45 | 深色主题截图中对比度高，不误报 |
| 过曝 | 均值 > 225 且对比度 < 20 | 浅色截图对比度通常 > 30，不误报 |
| 反光 | 亮像素占比 > 10%、均值 < 205、最大亮连通块 > 1.5% | 白纸均值 > 215 走不到这条；黑底白字是碎笔画，连通块小 |
| 明显倾斜 | \|角\| ≥ 10° | 1~10° 归自动摆正，不提示重拍 |

门控**只提示、不拦截**：弹窗给「仍然识别」与「重拍 / 换一张」；深色截图、浅色截图、黑底白字都有反例测试钉住。

## 3. 自动摆正

- 投影法：把缩略图按候选角度剪切，逐行求均值再算行均值的方差；文字行对齐时方差最大。
- 粗搜 2° 步（-12°~12°）→ 细搜 0.5° 步；最优角相对 0° 的投影方差增益 < 3% 时判为水平（返回 0）。
- 只在 1° ≤ |角| ≤ 12° 时旋转，避免无意义重采样；旋转失败（OOM 等）原样返回，不阻断识别。
- 符号约定：正 = 内容向右下倾（顺时针）；校正时传负角度。

## 4. 低置信度二次识别

- 第一遍 rec 的 CTC 置信度低于 0.72 的行，把检测框四边扩 12%，再按行高放大 1.6x（行高 < 40px 时 2x）重识别；
- 最多重试 8 行；择优规则（纯函数 betterReading）：
  1. 新读法空白 → 保留旧；
  2. 文本相同且分数更高 → 保留文本、更新分数；
  3. 新分比旧分高 0.02 以上 → 用新读法；
  4. 旧分本来不及格且新分更高 → 用新读法；
  5. 其余保留第一遍（防止放大过采样读错）。
- 二次识别只对 rec 局部重跑，不重新 det，也不引入第二套模型。

## 5. 置信度路由（预览页）

- 行号即导入解析的行号（1 基）：照片里一行一题时，低置信度行可以被精确定位到具体条目；
- 单行分数 < 0.72 视为低置信度；整批字符加权均值 < 0.85 或照片质量有问题时也会提示；
- 预览页顶部常驻一条提示（照片问题 / 摆正角度 / 置信度 / 二次识别行数），
  并写明「已默认剔除 N 行低置信度内容，核对后可勾回」；
- 低置信度行默认剔除（对应勾选框不勾），用户核对后可逐行勾回；这不是数据库里的持久队列，
  而是入库前的最后一道人工确认。

## 6. 没做的事（下一阶段）

1. **透视校正 / 弯曲书页展平**：只做了角度旋转，边缘检测+四点透视与 dewarp 仍需 native/OpenCV 或模型；
2. **版面分析 / 题目切分**：仍按「一行一题」的文本格式解析，没有 YOLO 版面模型；
3. **公式识别**：图片里的公式仍只作为普通文本进入；Word 原生公式走既有的 OMML → LaTeX 路径；
4. **持久化校对队列**：当前只做到入库前默认剔除，题目表还没有 needsReview 列；
5. **300 张真实题目评测集**：目前是合成图 + 真机点测，尚无自动化 CER/WER 回归；
6. **用户纠错沉淀**：未新增纠错日志表（隐私上只应留在本地、默认不导出）。

这些在 v3.7 的发布说明里如实列为已知限制，下一步按「版面切题 → 公式占位 → 纠错闭环」推进。
