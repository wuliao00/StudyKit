# StudyKit v2.4 设计：习惯的玩、守、约

日期：2026-09-22　分支：`feat/v2-visual-motion`（起点 `cd2cb65`）
参照素材：小计划真机截图（监督计划 / 牛X功能）、Qoder 热力图贪吃蛇（用户提供的图3/图4）

## 0. 一句话结论

这一版给"习惯"补三样东西：**玩**（打卡热力图变成可玩的贪吃蛇棋盘）、**守**（专注一场 + 打卡规则三件套，
修掉"熬夜到凌晨打卡算断签"这个真实缺陷）、**约**（自我契约，监督计划的离线替身）。
外加时段分类与整理。五批交付，每批独立过 CI、可装 APK。

## 1. 论文依据（全部已核实；每批用哪篇标在批次里）

## 2. 批次一：贪吃蛇（图3/4）

**目标形态**（照 Qoder 那版）：习惯卡上加「玩一把」入口 → 出现一块 **7 行 × 20 列的棋盘**
（GitHub 贡献图式：一行是星期几、一列是一周，一格一天，**打过卡的格子高亮**），
蛇 = 发光圆角条（`success` 色），🍓随机落格（避开蛇身），左上「← 返回热力图」（退出回原卡片），
底部「得分 / 最高分」。

**两处与 Qoder 版的差别（这张图存在的理由）**：
1. **金果**：果子落在**打过卡的格子**上时是金果 +25，普通果 +10 —— 玩过一把之后
   "哪些天打了卡"在脑子里多了一层肌肉记忆。注意不是"今天已打卡"（那太窄，用不上历史数据）。
2. **展示用的单行滚动轨道保持原样不动**：游戏是叠加的一个模式，不是第三次重画历史图。
   棋盘只在玩的时候生成，数据源与轨道同源（同一个 habit 的打卡日集合）。


- 控制：滑动（上/下/左/右，与既有卡片滑动判定同一个工具函数，最小间隔 120ms 防连滑误触）；棋盘边缘即墙。
- 节奏：150ms/格起步，每吃一个 −2ms，封顶 90ms。
- 最高分：`app_settings` 两个 key（`snake_best`），不建表。
- **架构红线**（前两版贪吃蛇连错两次的教训）：游戏逻辑全部抽进 `ui/habit/SnakeGame.kt`，
  **零 Compose、零 Android**（给定 seed 的随机数由调用方注入），JVM 单测钉死：
  移动与转向（180° 掉头必须无效）、撞墙、咬自己、吃果（长度+1、加速）、
  两条计分分支、空棋盘/1×1 棋盘不崩、1000 步无 NaN。
  UI 只剩渲染 + 手势，坏也坏在看得见的地方。
- `reduceMotion` 为真：去掉发光拖尾动画，游戏逻辑与计分不变。
- **明确不做**：音效、震动、道具、多蛇、穿墙模式。

## 3. 批次二：打卡规则三件套（含一次 v6 迁移的半边）

设置页新增「打卡规则」卡，三项：

1. **每天开始时间**（默认 00:00，可选 00/02/03/04/05 点）：凌晨 0~3 点打卡记入**前一天**。
   影响面：连续天数（`StudyStreak` 重写为接收 boundary 参数）、日历归属、首页"今日"分组的当日判断。
   这是修真实缺陷，不是加花样 —— 现在的实现写死自然日，熬夜用户天天被断签。
2. **允许补打卡**（默认开）：日历上点过去 7 天内的空格 → 确认 → 记 `is_makeup=1`。
   连续天数**不断**，但日历上补的格用描边/降饱和区分，统计里单列"补了 N 次"。
   论文口径就写 Lally 那句：漏一天不毁自动性，清零才是反科学的。
3. **限制打卡时段**（默认关）：开启后给一天两个时间点，窗口外打卡按钮禁用并说明为什么。

## 4. 批次三：专注模式

- 任一习惯的打卡弹层加「专注一场」：时长 15/25/45 分钟（25 默认）。
- 全屏倒计时页：剩余时间大字、当前习惯名、一个「结束并记录」与「放弃」。
- 中途放弃 → 二次确认 + 一句 Leroy 的话（"被打断后注意力会残留在这里"），**不计打卡量**；
  正常结束 → 分钟数写入该习惯当天的 `check_ins.amount`（与既有数量型打卡同语义，即小计划的"计时打卡"）。
- 计时以 `elapsedRealtime` 记起点、回前台补算，**不信 UI 倒计时**；进程被杀视为中断，不记量，下次启动说明一句。
- 统计：首页"今日"行加"专注 X 分钟"。

## 5. 批次四：时段分类 + 计划整理

- `habits.category`：任意/早晨/上午/中午/下午/傍晚/晚上（默认任意）。习惯列表按"今日"分组列出，
  当前时段排最前 —— 依据是 Gardner 2021：**绑例程（"睡前"）比绑钟点（"22:30"）更易成习惯**。
- `habits.sort_order`：长按拖动排序。
- 「整理」页：批量改分类、拖动排序、归档（`archived=1`，列表默认隐藏，可查）。

## 6. 批次五：自我契约（监督计划的离线替身）

- `contracts` 表：`habit_id`、目标（**结构化**：到截止日累计打卡 ≥ N 次 —— 机器能判定，不收自由文本当判据）、
  承诺文案（自由文本，展示用）、违约后果（自由文本）、签名（昵称+日期）、状态（进行/达成/未达成）。
- 创建页给 if-then 模板（Gollwitzer 1999）："如果到了【场景】，我就【动作】"，字段化填空。
- 到期自动对账：达成给一个整页的仪式（不是 toast），未达成把当初自己写的后果原文摆出来。
- 论文口径照实写：这是 Ariely 意义上的 precommitment，**没有外部监督人**，约束力弱于图1 的真人监督 ——
  界面上第一句话就说清这一点，不吹。

## 7. 数据迁移（一次 v5→v6 做完全部 schema）

`check_ins` 加 `is_makeup INTEGER NOT NULL DEFAULT 0`；
`habits` 加 `category TEXT NOT NULL DEFAULT 'ANY'`、`sort_order INTEGER NOT NULL DEFAULT 0`、
`archived INTEGER NOT NULL DEFAULT 0`；
新建 `contracts` 表（批次五用，但表在 v6 一次建好 —— 用户已经为升级冒过四次险，能一次绝不两次）。
迁移 SQL 与 Room 生成的 DDL 逐字一致（`exportSchema = false`，老规矩），真机走查含 v5→v6 原地升级
（备份库推回法，已验证过三次）。

## 8. 明确不做

- 一切需要后端/账号的：真人监督、团队计划、计划广场、贴贴、微信通知、云端排行。
- 贪吃蛇的音效/震动/道具；专注模式的白噪音；契约的金钱质押（真金白银的 deposit contract 有文献，
  但让 app 收钱是另一回事，不在这一版）。

## 9. 风险

| 风险 | 缓解 |
|---|---|
| 贪吃蛇第三次做错 | 逻辑与渲染彻底分离 + 黄金轨迹单测先行（本设计的最高优先红线） |
| 日界改动悄悄弄脏历史统计 | `StudyStreak` 重写时旧口径用例全部保留并断言"boundary=00:00 时结果与旧逻辑一致" |
| v6 迁移在真机升级翻车 | 老三样：备份库先行、迁移后 integrity_check、拖回真机走一遍（已演练四次） |
| 专注计时被杀进程 | 以"中断"如实记录，不伪造数据 |
| 自我契约约束力存疑 | 界面第一句话就写"没有监督人，约束靠你自己"，不吹 |
