# StudyKit v2.5 设计：检索优先（闸门 + 预测试）与一批文案更正

日期：2026-09-29 状态：已确认，待施工
范围来源：一份外部写的《学习科学证据 × 你的 App 优化方案》。那份文档是照截图推断的，
本文档只采纳**核对过代码之后仍然成立**的部分，并写明哪些是它的误判、哪些刻意不做。

## 0. 先记着：那份文档的三个误判

后续施工的人可能会照着那份文档改已经对的东西，所以先钉住：

1. **它以为排期还是固定档位、该上 FSRS。** 实际 `data/memory/MemoryModel.kt:215-229`
   已是半衰期模型（`intervalDays = h·log2(1/target)`，代入冷启动能复现墨墨真机"认识→35 天"
   的量级，见单测 `reproduces_the_interval_printed_on_momo_buttons`）。**不要动这个模型。**
2. **它以为"连对两次永久出队"还在。** 那是 v4 的旧行为；现在 `MASTERED` 只是展示标签，
   判据是单次 `half_life_days >= 7`（`ui/study/StudyViewModel.kt:104-106,223-227`），
   出队判据是 `next_review_at > 0 AND <= now`（`data/dao/WordDao.kt:24-33`），
   v5 迁移里还专门写了防洪逻辑（`data/AppDatabase.kt:156-167`）。
3. **它把"明日预计复习 N 词"当新功能。** `tomorrowCount` 与 7 天预测柱都已存在
   （`StudyViewModel.kt:155`、`StudyHomeScreen.kt:168`、`StatsViewModel.kt:41,61-65`），
   只有 N=0 时才显示"明天没有排期"。

## 1. 目标

两件事，都**不碰 Room schema、不加表、不做迁移**：

- **S1 文案与展示层**：修掉一处与证据冲突的说法、一处过时描述，补一处"预测保留率"展示，
  加一处诚实说明。
- **S2 检索优先**：把"看答案之前先回忆"变成真闸门；新词第一次出现时给一轮预测试。

非目标（写清楚是为了不被顺手做掉）：
交错练习、信心评级、错题自动排期、书摘进复习队列、周达标率、小贴士系统、预测试的度量。
理由见 §5。

## 2. S1 明细

### 2.1 习惯页空状态去掉「21 天」
`ui/habit/HabitListScreen.kt:354` 现为 `caption = "每天坚持一小步，21 天养成一个习惯"`。

改成：**「每天坚持一小步，漏一天不算断」**

为什么不换成「66 天」：66 是 Lally et al. 2010 的中位数、范围 18–254。把它印在空状态上
等于又立一个会被当成 KPI 的数字，而这里真正要传达的是"漏一次不毁掉养成"——
那个才是降低早期流失的点。**不要再写任何具体天数。**

全仓核查过：界面文案里「21 天」的说法**仅此一处**；其余 `21` 都是默认值/选项
（`entity/Habit.kt:14`、`repository/HabitRepository.kt:22`、`HabitCreateScreen.kt:46,66`、
`DemoSeeder.kt:115,127,136`），不是宣称，不动。引导页、免责声明、README 均无此说法。

### 2.2 引导页三档口径
`ui/onboarding/Onboarding.kt:118` 现为「复习是卡片翻面：认识 / 不认识决定它下次什么时候出现。」
实际自评是三档 `RECALL / VAGUE / FORGET`（`data/memory/MemoryModel.kt:17`）。
改成三档口径，并保留"模糊也算想起来、只是难度会涨"这层意思（模型里 VAGUE 是
h 走成功支、d 走失败支，见 `MemoryModel.kt:132-134`，界面说法不能和它对不上）。

### 2.3 首页"明日预计复习 N 词 · 到时候大约还记得 X%"
现状：`StudyHomeScreen.kt:168` 在 N=0 时显示"明天没有排期"，N>0 时只有个数。
改成 N>0 时：**「明天预计复习 N 词 · 到时候大约还记得 X%」**，N=0 时**保留原句**
（没排期却说"记得 0%"是废话）。

X 的算法：对明天到期的那批词，逐条用
`MemoryModel.recallProbability(gapDays = (明天到期时刻 - last_review_at)/天, halfLifeDays)`
取**平均**。`recallProbability` 在 `MemoryModel.kt:109-115`，全库均值的用法可参考
`MemoryHealth.kt:156-160`。

**"明天"必须复用现有 `tomorrowCount` 的口径**（含 `AppSettings.dayStartHour` 那个
"一天从几点开始"的边界，见 `Settings.kt` 里 `dayStartHour` 的 KDoc）。
理由：N 和 X% 是同一批词的两个说法，各自算一遍就会打架——出现"明天 12 词"却按另一批词算保留率，
那是那种没人报错、但整行数字没意义的错法。**先读现有 `tomorrowCount` 怎么算的，用同一个边界。**

实现要点：`WordDao.kt:113` 现在只返回 `next_review_at`、`:122` 只返回 `half_life_days`，
两者不 JOIN。**补一条投影查询**（同一批行里同时取 `next_review_at`、`half_life_days`、
`last_review_at`），不要分两次查再在内存里配对——那会拿到两个不同快照，
本仓被 Room 的"逐条失效"坑过一次（见 §6 风险）。

### 2.4 错题页诚实说明
错题的复习时间是**手动**的：`ui/mistake/MistakeDetailScreen.kt:327-329` 三颗快捷项
（明天/三天后/一周后）→ `MistakeViewModel.kt:285-291` → `entity/Mistake.kt:22` 的 `review_at`。
在错题详情那块加一句说明：**复习时间由你自己定，这里没有算法排期**。
只加文案，不改逻辑。

## 3. S2 明细

### 3.1 闸门：先看答案之前算不算"回忆过"
现状（`ui/study/CardStudyScreen.kt`）：
- 点卡片可翻面（`:438`）；
- 「认识」按钮要求 `flipped`（`:507`）；
- **左右滑动明确不要求翻面**（`:293` 注释："语义与墨墨一致：左右滑都不要求先翻面即可评价"）；
- 卡下三档自评行 `GradeRow`（`:763-788`）也不要求翻面。

设计：**闸门开启且卡片未翻面时，滑动不结算，而是触发一次翻面**（卡片弹回原位 + 翻面），
翻面之后滑动与三档自评按原语义工作。

为什么不是"拦下滑动什么都不做"：这个卡片的主动作就是滑，点了没反应会被当成 bug。
把第一次滑动**变成**翻面，强制的是"答案先于评分出现"，不是"不许摸"。

同时：三档自评行 `GradeRow`（`:763-788`）在**闸门开启且未翻面**时置灰（`enabled = false`），
沿用现有 `AppButton` 的禁用态，不新造视觉。**闸门关掉时必须完全退回今天的行为**——
这是"可关"承诺的全部内容，不是留着半截拦截。

一次性说明：闸门**第一次**真正拦下一次滑动时，给一条带「知道了」的说明，
文案要点是"先自己想一想，再翻面对答案——想不起来也没关系"。
**范围是每次安装一次**（不是每天一次、不是每次会话一次）：`AppSettings` 加
`recallGateHintSeen: Boolean = false`，点「知道了」时置真，此后不再出现。
两个新字段都落 `app_settings` 键值行，不需要迁移。

### 3.2 开关
`data/Settings.kt` 的 `AppSettings` 加 `recallBeforeGrade: Boolean = true`。
`app_settings` 是键值表（`Settings.kt:19` 的 KDoc 写明），所以**加字段 = 加一行，不需要迁移**。
设置页加一行开关。

**这条设置必须有消费点**：`Settings.kt:21-22` 立着一条规矩"每一条都必须有消费点"，
上一版就是按它砍掉过四个"存了没人读"的开关。消费点是 `CardStudyScreen` 的闸门判定，
测试要覆盖"关掉之后滑动直接结算"。

### 3.3 新词预测试（三选一）
触发条件（三条同时成立）：
1. 闸门开着（复用同一个开关，不新增第二个设置项）；
2. 该词是新词：`word.status == Word.STATUS_NEW && word.lastReviewAt == null`（`Word.kt:14,27`）；
3. 能凑出 3 个**互不相同**的释义。

出题：正确项 = 该词 `meaning`；干扰项从同一本词库（`source_list_id` 相同）随机取 2 条
别的词的 `meaning`，**按释义文本去重**（同词库里有重复释义会给出两个一样的选项）；
`source_list_id` 为 null（手工/粘贴/导入词）时退回全表取。三项打乱顺序呈现。

**不足 3 条可用释义时整轮跳过**，直接进原有翻面评分流程。
不许退化成"二选一"或"只有一个正确项"——那是假预测试。

流程：选一个 → 立刻标出正确项 → 用户确认后进入原有的翻面+三档评分。

**预测试走完即视为已翻面**（`flipped = true`）。理由：这时释义已经在屏幕上，
再逼用户点一次翻面去看他刚看过答案的东西，是纯粹的空转，而且会让闸门看起来"坏了"
（明明看得见答案，滑动却不结算）。所以预测试是**闸门的一个合法通过路径**，
不是叠在闸门上的又一道。

反过来说，预测试期间**不允许**评分：正确项标出后到用户点确认之前，三档自评保持禁用，
避免"看一眼选项就顺手按认识"。

**猜的结果一律不落库。** 不写 `word_reviews`，不写任何表。
理由：`word_reviews` 的 `gapDays/pAtReview/hBefore/hAfter` 是给以后校准模型用的样本
（`StudyViewModel.kt:245-253`），而"猜"不是对已存记忆的提取，混进去样本语义就脏了；
`applyReview` 还会把 `last_review_at` 往前推，新词第二次评分的 Δt 锚点会跟着错。
`:236-238` 那段注释已经在专门防"污染以后的校准样本"。

## 4. 测试

1. **纯函数单测**
   - 闸门判定：`闸门开 + 未翻面 + 滑动 ⇒ 翻面、不结算`；`已翻面 + 滑动 ⇒ 结算`；
     `闸门关 + 未翻面 + 滑动 ⇒ 结算`（开关真的有消费点）。
   - 干扰项选取：去重生效；可用释义不足 3 条 ⇒ 返回"跳过"；正确项位置不固定（多次调用覆盖到不同位置）。
   - 明日保留率：给定一批 (到期时刻, h, last_review_at) ⇒ 平均值符合手算；
     且**分词边界与 `tomorrowCount` 一致**（同一批输入两边数出来的词数必须相同）。
   - 预测试完成后：`flipped == true`、闸门视为已通过、此时滑动可以直接结算；
     以及"预测试进行中三档自评不可用"。
2. **Robolectric 渲染守卫**（本仓已有 `ContractRitualRenderTest`、`CheckInSheetRenderTest` 先例）
   闸门开、未翻面时注入一次滑动手势 ⇒ 断言 `onGrade` **没被调用**；翻面后再滑 ⇒ 被调用。
   这条只有真渲染测得到，纯函数测不到手势路径。
   注意本仓已知坑：`ui-test-manifest` 必须是 `debugImplementation`；一个测试里只能
   `setContent` 一次；dialog 收不到注入的点击。
3. **一条事实守卫**：断言习惯页空状态文案不含「21 天」。
   这是唯一能防止有人把那句改回去的机制，而它是一句被原研究团队公开辟谣过的说法。
4. **全量回归**：`testDebugUnitTest` 跑**两遍**（本仓有随机红前科：Robolectric 跨类污染、
   轮询/时序类测试），两遍都 0 失败才算上岸。
5. **真机走查**（adb，vivo `35152127910030J`）：开关两个状态、新词首卡预测试、
   词库不足 3 条时的跳过路径、闸门首次拦截的说明只出现一次。
   注意这台机**整机没有可用 DNS**，任何联网功能在它上面验不了；
   装包会弹 vivo 安全守护确认页，要用 uiautomator 的 bounds 点勾选框再点「继续安装」。

## 5. 为什么那些项被推后（不是"不重要"，是"代价被文档低估了"）

| 项 | 推后原因 |
|---|---|
| 预测试的度量 | 要新表 ⇒ Room v6→v7 迁移。而本仓**没有任何 migration 测试**、`exportSchema = false`（`AppDatabase.kt:50`），迁移代码自己的注释写着"CI 全绿也测不出来"（`:84-86`）。要先补测试网再谈加表。 |
| 错题自动排期 | 错题**没有逐次评分历史表**，模型拿不到 `Δt/p` 自变量。这不是换算法，是先补一条数据链。 |
| 信心评级 / 超纠正排期 | 加列 ⇒ 同样撞上面那条迁移风险。另外 `reaction_ms` 已经在入库但**故意不进模型**（`StudyViewModel.kt:203-205`：自我评分的犹豫时长和真实提取时长不是一回事），别把它当信心维度直接拿来用。 |
| 交错练习 | 现在严格块状（`QuestionDao.kt:18` `WHERE subject=? ORDER BY id LIMIT 10`）。要做需要先定"什么时候算达到基础正确率"，那是个口径决定，不是代码活。 |
| 小贴士系统 | 那些 tips 的触发点（"首次做错""首次漏打卡"）大多还不存在，没有可挂的地方。排在功能后面。 |

## 6. 风险

- **滑动语义变更**是这个方案里唯一碰核心手感的地方。墨墨的既有习惯是"不翻面也能滑"，
  改了以后靠 §3.2 的开关兜底，默认开。
- **Room 逐条失效**：新加的投影查询必须**一条 SQL 拿全三个字段**，不能分两次查。
  本仓真实踩过：`settleDue` 逐条 `await update()` ⇒ 每张失效一次 ⇒ 观察者拿到半新半旧快照。
- 文案改动也要过真机：`caption` 变长可能折行，本仓有过"为救折行加 `weight(1f, fill=false)`
  结果把名字压成省略号"的先例。
