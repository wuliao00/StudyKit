### 1.5 由事实推出的五条硬结论

1. **模型本身不是主要阻塞**：LLM/语音三个包都有可达 + 已量化/可直接跑的件（ModelScope MNN 预转换、GitHub sherpa 模型）；真正卡住的是**运行时集成 + 真机 + 门的数据**。
2. **MNN 是 LLM 最贵的一环**：没有现成 Maven AAR，官方 Android zip 不含 LLM 封装；自编 MNN LLM（NDK 26.1 在）可行但一天不够，且没设备验证性能门。
3. **sherpa-onnx AAR 会引入第二个 ONNX Runtime**：仓内已有 `onnxruntime-android:1.29.0`，sherpa AAR 自带 ORT .so；打包时要么用 `static-link` 变体，要么做一次真机验证，**这是集成任务的前置决定**。
4. **StructureV3 / 去手写的阻塞在"产线不在模型"**：Paddle→ONNX 转换、int8 量化、blocks 阅读序、去手写保真门，任何一项都不是一天；且目前**没有可访问的去手写 ONNX**。
5. **体积账必然超 600MB**：见 §2.6，`BudgetGuard` 不是锦上添花，是必须先在包管理里落地的拒装逻辑。

### 2.2 LLM 解释包为什么一天做不完

文档 L2175 给的是产线：Qwen3-0.6B-Instruct → `llmexport.py --quant 4` → `libMNN_Llm.so` 会话管理（充电 warmup / 后台流式 / 可取消 / OOM 降级）。实测后的真实路径：

- **模型导出可跳过**：ModelScope `MNN/Qwen3-0.6B-MNN` 已经是 MNN 格式（`llm.mnn` + `llm.mnn.weight` + `tokenizer.txt`），433.4MB，可直接作为"已量化模型包"的内容。这省掉 Python 导出一大块，但**没有省掉运行时**。
- **运行时三选一，都是一天以上**：
  1. 自编 MNN LLM：本机 NDK 26.1 + cmake 齐全，但 2 核 8GB 编 MNN（含 LLM 模块）预计 30–90 分钟起，且需要写 JNI 会话管理（加载/流式/取消/OOM 降级），之后还要真机跑性能门；
  2. 用 mnn-llm 的预编译库：需要确认其 Android 库的许可证、ABI 与 NDK 版本，且它通常按 app 示例提供，不是可依赖的 AAR；
  3. 换 ONNX Runtime GenAI：Maven 上**没有** `onnxruntime-genai-android`（实测），要自编；换框架等于重写产线。
- **门的代价**：性能门（≥12 tok/s、RSS<1.5GB、10 次无热崩）需要**真机**；质量门（50 卡 golden × 三人 rubric、编造公式 = 不过）需要 **D7 数据集**（文档 L2280 表 D7、L2286 成本 2 人天）+ 人工评估。一天内连数据都造不出来。
- **安全门**（注入 fixture 10 条、零网络断言进 CI）可以在 JVM 层做一半（JSON 契约解析、注入拒绝的纯逻辑），但没有运行时就是空转。

**结论**：LLM 包一天内只能占位。占位的**诚实做法**：`PackManifest` 里 `downloadable=false`、UI 显示「暂未上架（端侧运行时就绪后开放）」；**不要**写"下载后即可用"。

### 2.3 TTS / ASR 为什么也做不完

- 模型可下（30.1MB / 70.6MB 实测 206），**AAR 也有**（`sherpa-onnx-v1.13.8-android.tar.bz2` 44MB），但：
  - AAR 自带 ONNX Runtime 的 `libonnxruntime.so`，与仓内 `onnxruntime-android:1.29.0` 的 .so **同名冲突**；要么用 static-link 变体、要么保留两份（APK 体积、符号、加载顺序都要实测），**这一步没有设备/仪器就验证不了**；
  - 文档的验收门是**声学/延迟**（首音、RTF、partial 延迟、CER），全部要真机 + D6 朗读集（30 条、3 口音 × 10，签声音授权）；
  - 背诵验收还要接打卡流程与"未完成不扣分"的中断语义（L2043），是产品层工作，不是包管理。
- **一天内可交付的只有"包管理里的 voice 两行 + 占位下载 URL"**，不能碰功能。

### 2.4 高配结构包（StructureV3）

- 文档把估算从 150MB 下修到 75-90MB（layout int8 30 + SLANet int8 20 + formula int8 25），前提是 **ONNX + int8**。ModelScope 上可下的是 **Paddle 原格式**：`PP-DocLayout-L` 124.1MB、`PP-FormulaNet_plus-L` 701.4MB；表格模型（SLANet-plus）**未在 ModelScope 定位到**（`PaddlePaddle/SLANet-plus` 404）。
- 转换链：`paddlepaddle` + `paddle2onnx` + 量化（PaddleSlim/onnxruntime quantization），本机 Python 3.13 与 paddle 的兼容性是未知数（**S 级风险**，需 3.10/3.11 venv）。
- 集成链：ORT 已有（幸），但 blocks 流水线（矫正/去阴影 → layout → 阅读序拼接 → 表格 HTML / 公式 LaTeX / 图裁切 → v2.9 预览建卡流）是**跨模块产品功能**，且 v2.9 预览建卡流本身还没做（本仓无 OCR 预览建卡模块，只有 `QuestionPhotoImport` 直接 OCR）。
- 门：layout mAP ≥0.85 / 表格 TEDS ≥0.80 / 公式 ExpRate ≥0.55 + 低置信保留原图，全部要 D2/D3 集（文档估 5 人天）与人工标注。
- **结论**：占位。**建议不要把它和 LLM 同时上**（两者体积互斥，文档也这么建议）。

### 2.5 去手写（de-handwrite）

- 唯一的公开可用权重线索是 HuggingFace `g-ronimo/lama`（mobile-lama 系），而 **HuggingFace 实测不可达**；GitHub 上没有找到可直接用的 mobile-LaMa ONNX 发布件。
- 退路：① 找 ModelScope/网盘镜像（未找到）；② 用 torch 版 LaMa 转换（需要 torch + 一次 200MB 级权重 + 转换脚本）；③ 用更小的替代 inpainting 模型（换模型 = 换门）。
- 门：印刷区 SSIM ≥0.95（不伤字）+ 30 样张主观 ≥4/5 + 低置信回退原图，D4 集（文档估 1 人天）＋人工。
- **结论**：占位，且**建议 v3.1 首批里砍掉**（体积 45MB 换一个最不确定的模型源）。

### 3.3 `PackManifest` schema v1

```jsonc
// filesDir/model-packs/<id>/manifest.json —— 安装成功后只读；sha256 校验通过才保留
{
  "schema": 1,
  "id": "voice-tts",                    // [a-z0-9-]{3,40}
  "kind": "VOICE_TTS",                  // LLM | VOICE_TTS | VOICE_ASR | STRUCTURE_V3 | DE_HANDWRITE | EMBED
  "displayName": "语音包（朗读）",
  "version": "1.0.0",
  "minApp": "3.1.0",
  "sizeBytes": 31545856,                // Σ files[].bytes，下载完成后由代码写入，不抄文档
  "downloadUrl": "https://…",           // 占位阶段为 null；UI 显示"暂未上架"
  "files": [
    { "path": "model.onnx", "bytes": 31457280, "sha256": "…64 hex…" },
    { "path": "tokens.txt", "bytes": 88576,   "sha256": "…" }
  ]
}
```

校验规则（`PackManifest.fromJson` 返回 `Result`/抛 `PackManifestException`，单测逐条钉）：
1. `schema != 1` → 拒；`id` 不匹配正则 → 拒；`kind` 未知 → 拒。
2. `files` 非空；每个 `path` 必须是**相对路径且不含 `..` 与盘符**（防目录穿越）；`sha256` 必须 64 位 hex；`bytes > 0`。
3. `sizeBytes == Σ files.bytes`（不许手填不一致）；`downloadUrl` 可空，非空时必须是 `https://`。
4. 未知键忽略（前向兼容）；缺 `minApp` 视为不限制。

> 文档 L1728 给语义包设想的 manifest 字段（name/ver/sha256/bytes/dim:512/maxLen:128/ortMin/vocabSha）是本 schema 的子集：v1 用 `files[]` 逐文件 sha 覆盖多文件包；`dim`/`vocabSha` 这类 kind-specific 字段**等语义包真正落地时**再加 `extra` 对象（本计划不实现 extra，也不假装它们已存在）。

### 3.4 `ModelPackStore`（文件即真相）

目录布局（`filesDir/model-packs/`）：

```text
model-packs/
├─ voice-tts/                 # 已安装
│  ├─ manifest.json           # 只读、参与校验
│  ├─ state.json              # {"enabled":true,"installedAt":<ms>}
│  └─ payload/                # ← manifest.files[].path 的相对根
│     ├─ model.onnx
│     └─ tokens.txt
└─ voice-asr.partial/         # 下载中（staging，崩溃/取消后可被下次启动清理）
```

API（实现签名建议）：

```kotlin
class ModelPackStore(private val root: File) {
    fun dirOf(id: String): File                 // 只接受合法 id，否则抛
    fun stagingDirOf(id: String): File          // <id>.partial
    suspend fun list(): List<InstalledPack>     // 目录扫描 + manifest 解析；坏目录跳过并计入 skipped
    suspend fun installedBytes(): Long          // Σ payload 文件字节（只计已安装）
    suspend fun commit(id: String, manifest: PackManifest): InstalledPack // 校验 sha → 原子 rename → 写 state
    suspend fun verify(id: String): VerifyResult // 逐文件 sha256；返回缺失/不匹配清单
    suspend fun setEnabled(id: String, enabled: Boolean)
    suspend fun delete(id: String): Long        // 删目录，返回释放字节
    suspend fun cleanupPartials(): Int          // 启动时清 .partial
}
data class InstalledPack(val manifest: PackManifest, val enabled: Boolean, val installedAt: Long)
sealed interface VerifyResult { data object Ok; data class Broken(val missing: List<String>, val mismatched: List<String>) }
```

要点：
- **原子安装**：下载完整 → 逐文件 sha256 校验 → 写 `manifest.json/state.json` 到 staging → `File.renameTo`（同分区）换成正式目录；失败/取消删 staging。
- **目录穿越防护**：`id` 与 `files[].path` 都要拒绝 `/` 开头、`..`、`:`；`dirOf` 的实现要先规范化再 assert `startsWith(root)`。
- **不缓存全局索引**：目录扫描是 O(packs)，包数 ≤6；避免"索引文件与目录不一致"的第二真相源。
- **坏包不 crash**：manifest 损坏 → 该包当"未安装 + 需要修复"呈现，`list()` 不抛。
- `installedBytes()` 只统计已安装包的 payload；与 `BudgetGuard` 的输入必须同一个函数（避免两套口径）。

### 3.5 `BudgetGuard`（文档 ⛔ 项，纯函数最好测）

```kotlin
    val newBytes: Long,
    val budgetBytes: Long,        // DEFAULT = 600L * 1024 * 1024
    val needFreeBytes: Long,      // max(0, installed + new - budget)
    val suggestRemove: PackUsage? // 能从"已安装"里腾出 needFree 的**最小**那一个（少删一点）
)
object BudgetGuard {
    const val DEFAULT_BUDGET_BYTES = 600L * 1024 * 1024   // 文档 L2220
    fun check(installed: List<PackUsage>, incoming: PackUsage,
              budgetBytes: Long = DEFAULT_BUDGET_BYTES): BudgetDecision
}
```

- 边界：`installed + new == budget` → **允许**（文档是 `>` 才拒）；超 1 字节 → 拒。
- 建议算法：候选 = 已安装且 `bytes >= needFreeBytes`，按 `bytes` 升序取第一个（少删）；没有则 `suggestRemove = null`，走"卸哪个都不够"的文案分支（新文案，见附录 B，需 Lead 确认）。
- **和实测体积一起测**：用 §2.6 的 433.4/100.7/90/45/30MB 做一条"五包全装必拒"的用例，这样体积账的矛盾在 CI 里可复现，而不是埋在文档里。
- 不负责"自动删"：BudgetGuard 只出决定与建议；删除必须用户确认（不可逆操作）。

### 3.6 `PackDownloader`（复用 `DictRemote` 的形状，但**不进 APK 打模型**）

- `suspend fun download(manifest: PackManifest, onProgress: (Float) -> Unit): DownloadResult`，`DownloadResult = Success(stagingDir) | Failed(reason) | Cancelled`。
- 连接：`HttpURLConnection`，20s connect/read，UA `StudyKit-PackDownloader`；**手动跟 3xx ≤5 跳** + 可读错误（照 `DictRemote.open()` 的思路；不必抽共用抽象，两份实现各自简单）。
- 进度：按 `Content-Length`；无长度时回调 `0f`（与 `DictRemote` 同口径），UI 显示 indeterminate。
- 下载前：`File.usableSpace > sizeBytes * 1.1 + 20MB`，不够直接 `Failed("空间不足")`，**不发请求**。
- 下载后：逐文件 `sha256`（`MessageDigest`，流式 8KB buffer）；不匹配 → 删 staging + `Failed("校验失败")`。
- 取消：协程取消 → `finally` 删 staging；中途异常同样清理。
- 不做断点续传（v1 明确不做；包里最大 433MB，Wi-Fi 场景可接受，写进 KDoc）。
- **可测性**：构造子注入 `openStream: (String) -> InputStream` 或 `fetcher: (url, onProgress) -> ByteArray`；单测用假 fetcher 覆盖成功/404/302/校验失败/取消；可选加一条 `com.sun.net.httpserver.HttpServer` 的真连接用例（JVM 可用；若 CI 上不可用就删，不硬撑）。
- 现实下载 URL（ModelScope 直链）**只放 manifest 种子，代码里不写死**；测试里用 `https://example.invalid/...`。
