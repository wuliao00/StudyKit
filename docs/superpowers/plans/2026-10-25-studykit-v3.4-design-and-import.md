# v3.4：学习设计工作台与题库文件导入

> 本文件记录实现口径，不替代 CHANGELOG。日期：2026-10-25。

## 1. 需求拆解

用户要的不是“让 AI 聊天”，而是八种**可复用的学习/教学设计流程**：

| 模板 | 用户的原始说法 | 落成的可操作产物 |
|---|---|---|
| 费曼学习 | 概念自查或知识理解 | 解释 → 缺口 → 类比 → 自测问题 |
| 习题带练 | 题型练习或解题思路梳理 | 例题 → 步骤 → 易错 → 变式 → 迁移提问 |
| 学会学习 | 调整学习方法或优化复习策略 | 目标 → 现状 → 证据 → 两周实验 → 复盘 |
| 互动工作坊 | 互动教学培训或实践活动设计 | 目标 → 破冰 → 核心活动 → 复盘 → 材料 |
| 系列课规划 | 系列课程规划或多课时教学安排 | 目标 → 递进主线 → 课时表 → 评价 |
| 逆向教学设计 | 围绕学习目标设计评价与教学活动 | 预期结果 → 证据 → 活动 → 迁移 |
| 核心素养备课 | 将素养目标转化为具体教学任务 | 素养表现 → 核心任务 → 量规 → 支架 |
| 螺旋式课程设计 | 同一概念的多轮学习与逐步深化 | 三轮设计 → 每轮“更深”的证据 |

**为什么不做 AI 生成**：应用是纯本地、无账号、无后端；引入模型会带来下载体积、隐私与
“每次输出不一样”的三重问题。模板拼装是确定性的：同样的字段永远得到同一份 Markdown，
可测试、可离线、可复现。这是产品约束下的正确解，不是功能缩水。

## 2. 数据模型

Room v11 → v12，只加一张表：

```sql
CREATE TABLE design_plans (
  id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
  uuid TEXT NOT NULL,
  mode TEXT NOT NULL,          -- DesignMode.name
  title TEXT NOT NULL,
  fields_json TEXT NOT NULL,   -- 字段键值，键排序稳定
  content TEXT NOT NULL,       -- 保存时刻的 Markdown 快照
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
)
CREATE INDEX index_design_plans_updated_at ON design_plans(updated_at)
```

`content` 是**快照**而不是每次渲染：模板文案以后改版，旧方案导出仍是保存时的文本。
`fields_json` 保留是为了继续编辑。两者都存，换来“可编辑”与“可复现”同时成立。

## 3. 生成契约

- 输入：`DesignMode` + 标题 + `Map<String,String>`。
- 输出：`# 标题` → `> 方法：…` → 若干 `## 段落` → `## 下一步`。
- 必填缺失：正文写 `（待补充）`，不虚构。
- 多行字段：逐行 `- ` 列表。
- 表格字段（课时安排、素养目标、量规）：`A | B | C` 转 Markdown 表；列数不符整段降级为列表，
  不拼半张错位表。
- 不接受未知字段键；旧字段不会冒进新正文。

## 4. 文件导入

- 纯文本：BOM → 严格 UTF-8 → 严格 GB18030 → 宽松 UTF-8。中文旧编码不乱码。
- DOCX：zip 里只读 `word/document.xml`，顺序扫描 `<w:t>` / `</w:p>` / `<w:br/>` / `<w:tab/>`，
  解 XML 实体；不引 XML 树，避免 Android 与宿主 JVM 的 `javax.xml` 差异。
- PDF：`pdfbox-android 2.0.27.0` 取文字层（按坐标排序）；空白时 `PdfRenderer` 渲染前 20 页，
  交给已有 PP-OCRv6。两条路分开，是为了可复制文字的 PDF 拿到精确原文。
- 上限：单文件 40MB；DOCX XML 8M 字符；OCR 20 页。全部在 IO 线程。
- `.doc/.wps`：先嗅探文件头；zip/docx 改后缀可直接读，真 OLE2/RTF 提示另存。
  不引 Apache POI（体积 +6MB、R8 风险），这条边界写进文档而不是假支持。
