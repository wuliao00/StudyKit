> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把题库练习轮次的出题顺序从「只按学科打散」升级成「文字上很像的题不许连着出，且被判为易混的对子强制同场、隔 3–5 题再遇」，用一个**纯函数的 `QueueBuilder`** 实现文档 §② 的两遍约束，并把相似度判定收进一个**可插拔的 `Simularity` 接口**——本计划只提供「词面（题干二元组 Dice + 考点标签地板）」这一个实现，嵌入向量实现留给语义包计划。

## 与文档的偏差（有意为之，实现时不要「照文档改回去」）

- **D1 不建 `card_embed` / `confusable` 两张表。** 文档为「384 维向量常驻 + 500 卡两两比对」准备它们，但本计划不产向量：填一张没人写的表要付 schema v10、迁移、迁移测试、以及将来语义包到位时的口径冲突。词面相似度对 ≤20 条的会话池当场算得起（Task 2 的记忆化把重复比对压成 0 次）。若语义包计划落地，这两张表**连同** `EmbedWorker` 一起在那份计划里开。
- **D2 sim 提供方 = 词面，不是嵌入。** 因此文档 L1266 的设置说明不能照抄（它会宣称一个不存在的依赖）。新文案只说代码真做的事，且收进纯函数 `semanticInterleaveHint()` 钉进测试。
- **D3 阈值分刻度。** `InterleavePolicy` 把阈值变成提供方带进来的数据。词面刻度（`tauHi 0.60 / tauLo 0.15 / drill 0.40..0.75`）是**未校准的初值**：它由「题干二元组 Dice 的分布」推来，没有经过 200+200 标注对验证。KDoc 与 CHANGELOG 都要写明「初值未经标注校准」。文档的余弦刻度以注释形式留在旁边，语义包到位时另开一份 policy，不复用词面值。
- **D4 「都在 3 天内到期」没有对应物。** 文档要求混淆对同时满足 `sim∈[0.7,0.9]` **且**都在 3 天内到期。但 `questions` 表没有 `next_review_at` 列——题不是按 FSRS 排期的到期集合，`getBySubject(subject, limit, offset)` 取的是录入序前 N 条。这条子句**去掉**，代之以「同一次抽取的候选池内」。不做「给题排期」的扩张：那是另一份计划的事，且会撞上 v3.0-B 的排期口径。
- **D5 有界窗口替代全尾扫描。** 文档参考实现的 `(i + 2 until q.size).firstOrNull {...}` 是每条最坏 O(n) 次 `sim`，500 条时是 12.5 万次查表——与文档自己的「500 due 构建 <50ms」相矛盾。本计划改成 `lookahead = 12` 的窗口 + 每轮一次单向前扫 + 最多 `maxRepairRounds = 4` 轮，换来**可证的查找上界**（Task 8 把它钉成断言）。
  - **原稿写的「每轮 `2·n` 步预算」已在 T3 评审中作废**：那条预算是为「换位后回退一格」的冒泡而加的保险，而回退一格本身被证明建立在一条假的相邻关系论断上（交换只动 `i+1` 与 `j`），连同预算一起删掉；没有回退时一轮扫描本身就是 O(n)，终止性显然。
  - **诚实的代价比原稿写的大**：一条题每轮最多前移一个窗口，所以**只有 `n - 1 > lookahead × maxRepairRounds` 时窗口才真的构成约束**。按生产取值那是 48 —— 而真实会话是 `QUIZ_SIZE = 10`（T5/T7 那一条路径），**也就是说在用户实际会用到的规模上，有界窗口与文档的全尾扫描行为完全相同**，这条偏差买到的是"规模上的可证上界"，不是"生产行为不同"。谁要是把 D5 当成行为差异来测试，会测不到东西（T3 的 22 条夹具就是这么白写的，换到 60 条才分得开）。
  - 查表上界由**两项**相加，`insertBuffer` 那项不能省（n=500、|pool|=500 时约为换位次项的 80 倍）：`n × (lookahead + 1) × maxRepairRounds` + `违反位置数 × maxRepairRounds × |pool| × 2`，另加 `report` 读数时的 `2 × (n - 1)`。生产代码的 KDoc 是唯一事实源，Task 8 的公式照它写。
- **D6 文档参考实现有四处会让结果不确定或索引错位，逐条改掉并各钉一条测试。**
  1. `q.removeAt(ib)` 之后仍用**旧的** `ia` 算插入位置：`ib < ia` 时整体左移一格，插入点偏一位；
  2. 第二遍 drills 会把第一遍修好的相邻**重新造出违规**（把 b 挪到 `a + gapLo` 时没人检查 b 的新邻居），而参考实现之后不再修；
  3. `(0 until q.size - 1).maxOf {...}` 在 `q.size < 2` 时抛 `NoSuchElementException`——单题轮和空轮是真的会走到这里；
  4. `for ((a, bs) in confusable)` 吃 `Map` 迭代序 = `HashMap` 顺序不定 ⇒ 同一批题两次组轮给出两种顺序，与仓内「确定性优先」直接冲突。
- **D7 开关默认关。** 词面阈值未经标注校准（D3）。默认打开等于**静默改掉所有现有用户刷题的顺序**，而他自己不知道。设置项存在但默认 `false`；打开才生效。
- **D8 只接题库轮次，不接词卡轮与模考。** `CardSessionQueue.compose`（词卡）这一支**没有学科维**（`words` 无 subject 列），也就没有文档要求的「回退到现有学科级交错」那一层——接进去等于新增一条没有回退路径的改动面。`startMockExam` 是卷面顺序，不该被练习启发式扰动（v2.9/v3.0-B 的卷面闸门一字不动）。错题重做队列同理不接。
- **D9 ⛔ 相邻率只在合成 sim 下验证。** Task 4 用「三簇近重复」合成夹具钉住 `unresolved.isEmpty()`，用一条**故意不可满足**的夹具钉住「修不好时如实上报」。真值（真实嵌入 + 真实题库 + 真机）留到语义包计划，本计划在 CHANGELOG 里明写这条没验。

```kotlin
package com.studykit.ui.study

import org.junit.Assert.assertEquals
import org.junit.Assert.assertTrue
import org.junit.Test

class TextSimilarityTest {

    @Test fun `归一化丢掉标点空白只留汉字字母数字`() {
        assertEquals("甲乙丙123abc", TextSimilarity.normalize("甲、乙 丙 123 ABC"))
    }

    @Test fun `归一化把字母转小写`() {
        assertEquals("abc甲", TextSimilarity.normalize("ABC 甲"))
    }

    @Test fun `归一化对空串返回空串`() {
        assertEquals("", TextSimilarity.normalize(""))
    }

    @Test fun `二元组长度 n 的串给 n 减 1 组`() {
        assertEquals(setOf("甲乙", "乙丙", "丙丁"), TextSimilarity.bigrams("甲乙丙丁"))
    }

    @Test fun `二元组单字符退化为单字符集合`() {
        assertEquals(setOf("甲"), TextSimilarity.bigrams("甲"))
    }

    @Test fun `二元组空串给空集合`() {
        assertTrue(TextSimilarity.bigrams("").isEmpty())
    }

    @Test fun `dice 自身对自身等于一`() {
        val g = TextSimilarity.bigrams("下列句子没有语病的一项是")
        assertEquals(1f, TextSimilarity.dice(g, g), 1e-6f)
    }

    @Test fun `dice 完全不相交等于零`() {
        assertEquals(0f, TextSimilarity.dice(TextSimilarity.bigrams("甲乙丙丁"), TextSimilarity.bigrams("戊己庚辛")), 1e-6f)
    }

    @Test fun `dice 任一集合为空给零不抛异常`() {
        assertEquals(0f, TextSimilarity.dice(emptySet(), TextSimilarity.bigrams("甲乙")), 1e-6f)
        assertEquals(0f, TextSimilarity.dice(TextSimilarity.bigrams("甲乙"), emptySet()), 1e-6f)
    }

    @Test fun `dice 半重叠等于三分之二`() {
        // {甲乙,乙丙} 与 {乙丙,丙丁}：2*1/(2+2) = 0.5
        assertEquals(0.5f, TextSimilarity.dice(TextSimilarity.bigrams("甲乙丙"), TextSimilarity.bigrams("乙丙丁")), 1e-6f)
    }

    @Test fun `题面相似只改标点后等于一`() {
        val a = "下列句子中，没有语病的一项是（　）"
        val b = "下列句子中没有语病的一项是"
```

```kotlin
package com.studykit.ui.study

/**
 * 词面相似度 —— v3.0-C 的相似度提供方之一，也是本仓当前唯一的提供方。
 *
 * 它**不是**语义模型：只比「题干去掉标点后剩下的字符二元组有没有重合」，外加一条考点标签的规则。
 * 之所以值得做，是因为题库里真正的连排事故恰好是它看得见的那一类 ——
 * 同一道改变个说法再问一遍（`下列句子中没有语病的一项是` vs `下列句子中，没有语病的一项是（　）`），
 * 连着出等于把答案送到用户眼前，交错对这一类是有效的。
 * 它看不见的是"意思相近但用词不同"（` velocity 变化越快` vs `加速度越大`），那类要嵌入向量。
 *
 * 值域严格落在 `[0, 1]`：二元组 Dice 的定义保证上界是 1，下界是 0；考点地板是个常量。
 * 所以阈值可以按同一把尺子放在 `InterleavePolicy` 里，不需要在这层做任何"像不像"的判断。
 *
 * ## 阈值刻度（重要，别和文档混用）
 * 文档 §② 的 `TAU_HI = 0.85 / TAU_LO = 0.30` 是给**余弦相似度**定的。字符二元组 Dice 的分布和它
 * 不是一把尺子：**预期分布（未在本仓实测校准）——无关题偏低、改说法的变式题偏高、标点差异不影响分值**。
 * 本仓没跑过标注集，所以不给具体区间：没量过的数字不写。按这把预期，把 0.85 照搬到 Dice 上，
 * 大部分变式题会算不上违规 ⇒ 相邻修复这一遍**很少触发**（只有归一化后完全同文的那些必然触发），
 * 阈值越偏高就越接近"开着和没开一样"（v3.0-B Task 7
 * 的闸门就是这么静默死掉的）。词面刻度定在 `LexicalInterleave.DEFAULT`（Task 2），
 * 并且是**未经 200+200 标注对校准的初值** —— 校准是语义包计划的质量门，不在这份计划里。
 */
internal object TextSimilarity {

    /**
     * 考点标签相同时的相似度地板值。
     *
     * `questions.concept_tag`（v2.7 起有这一列，`''` = 未标注）按定义就是"同一个考点的变式候选"，
     * 所以两题同标签 ⇒ 无论字面像不像都算易混。取 0.65f：落在 Task 2 的混淆区间
     * `[drillLo=0.40, drillHi=0.75]` 之内（于是会被 drills 强制同场、隔 3..5 题），
     * 又高于 `tauHi=0.60`（于是同时也触发"不许相邻"），两个约束方向一致，不打架。
     */
    const val CONCEPT_FLOOR = 0.65f

    /**
     * 只保留字（汉字/字母/数字），其余（中英文标点、空白、括号、序号、全角空格）一律丢掉，字母转小写。
     *
     * 用 `Char.isLetterOrDigit()` 判定：它对 CJK 为真，所以中文题干天然留下；
     * 全角字母数字（U+FF21 这类）同样被 `isLetterOrDigit` 判为真而保留成"全角形态"，
     * 与半角不是同一个字符 —— 题库里没这种混写，不为此加一层映射（加了也没人验证）。
     */
    fun normalize(text: String): String = buildString(text.length) {
        for (ch in text) {
            if (ch.isLetterOrDigit()) append(ch.lowercaseChar())
        }
    }

    /** 相邻两字符一组。长度 1 退化为单字符集合，空串给空集合（宁可不相似，也别把空串当相似） */
    fun bigrams(s: String): Set<String> {
        if (s.isEmpty()) return emptySet()
        if (s.length == 1) return setOf(s)
        val out = HashSet<String>(s.length - 1)
        for (i in 0 until s.length - 1) out.add(s.substring(i, i + 2))
        return out
    }

    /** Dice = 2|A∩B| / (|A|+|B|)。任一为空 ⇒ 0f（没有可比的东西，不硬造相似） */
    fun dice(a: Set<String>, b: Set<String>): Float {
        if (a.isEmpty() || b.isEmpty()) return 0f
        val small: Set<String>
        val large: Set<String>
        if (a.size <= b.size) { small = a; large = b } else { small = b; large = a }
        var inter = 0
        for (gram in small) if (gram in large) inter++
        return 2f * inter / (a.size + b.size)
    }

    /**
     * 题面相似度。同考点（都非空且相等）⇒ 至少 [CONCEPT_FLOOR]；否则只取字面 Dice。
     *
     * 空标签不参与判定：`'' == ''` 在数据里是"两题都没标考点"，不是"同一考点"。
     * 不这样收窄的话，未标注的题库（`concept_tag` 默认 `''`）会全场互相抬到 0.65，
     * 交错退化成"按 id 重排"，而用户看到的是"我的题全被判成易混了"。
     */
    fun questionSimilarity(stemA: String, tagA: String, stemB: String, tagB: String): Float {
        val literal = dice(bigrams(normalize(stemA)), bigrams(normalize(stemB)))
        val sameConcept = tagA.isNotBlank() && tagA == tagB
        return if (sameConcept) maxOf(literal, CONCEPT_FLOOR) else literal
    }
}
```

```kotlin
package com.studykit.ui.study

/**
 * 交错约束的**阈值口径**。`QueueBuilder` 里不许出现任何阈值字面量：
 * 同一把尺子的两个家会分别漂，漂开那天起「修完了」和「没违规」就不是同一件事
 * （v3.0-B 一整条 lane 反复栽的就是这个形状 —— "两处各说一套"）。
 *
 * 语义（全部沿用文档 L1243 的比较方向）：
 *  - [tauHi]：相邻两题相似度**严格大于**它即违规（`sim > tauHi` ⇒ 必须分开）；
 *  - [tauLo]：缓冲卡/换位候选必须**严格小于**它才算"足够不像"；
 *  - [drillLo]..[drillHi]：混淆带 —— 落在这里的对子被强制同场并隔开 [gapLo]..[gapHi] 题。
 *    下界以上才值得 drill（太不像不是混淆），上界以上不 drill（那是重复题，只该分开，不该成对出现）。
 *  - [topK]：每张卡最多记几个混淆伙伴（文档 L1227 的"仅同学科内 top-8"）；
 *  - [lookahead]：相邻修复往后找换位候选的窗口宽度（偏差 D5，把 O(n²) 换成可证上界）；
 *  - [maxRepairRounds]：相邻修复最多扫几轮（drills 之后要复扫，见 Task 4）。
 */
internal data class InterleavePolicy(
    val tauHi: Float,
    val tauLo: Float,
    val drillLo: Float,
    val drillHi: Float,
    val gapLo: Int,
    val gapHi: Int,
    val topK: Int,
    val lookahead: Int,
    val maxRepairRounds: Int,
)

/**
 * 词面提供方的刻度。**初值未经标注校准**（偏差 D3/D9）：
 * 五个阈值按「题干二元组 Dice 的**预期**相对位置」排布 —— 缓冲线要低于混淆带下界、混淆带要跨过相邻线、
 * 上界之上算重复题而不是易混题；同考点地板 0.65（`TextSimilarity.CONCEPT_FLOOR`）落在这条带里。
 * **本仓没有量过任何分布**，所以这里不写「无关题低于多少、变式题落在多少」这类没实测过的区间：
 * 写了就等于把猜测当事实，而下限 tauLo=0.15 与上界 tauHi=0.60 正是照这几个猜出来的相对位置定的。
 * 真正的校准门是 200+200 人工标注对
```

```kotlin
package com.studykit.ui.study

import com.studykit.data.entity.Question

/**
 * 相似度提供方。id 是各内容类型自己的主键（题库轮里就是 `Question.id`），
 * 提供方**不解释 id 从哪来** —— 这正是把词面实现换成嵌入实现时唯一要动的地方（计划 D1 留下的缝）。
 *
 * 约定（`QuestionSimularity` 与测试替身都要守住）：
 *  - `sim(a, a) == 1f`（自反）；
 *  - `sim(a, b) == sim(b, a)`（对称）；
 *  - 值域 `[0, 1]`；
 *  - 不认识的 id 给 `0f`（"没有依据"当作不像，绝不因为缺数据而阻断交错）。
 */
internal fun interface Simularity {
    fun sim(a: Long, b: Long): Float
}

/**
 * 题面相似度提供方：[QuestionSimularity] 是生产实现。
 *
 * 为什么要它而不是直接把 `(Long, Long) -> Float` 传来传去：`QueueBuilder` 在一轮修复里会
 * 反复问同一对（换位的窗口扫、插入前查两个邻居、drills 复扫），不记忆化的话重复计算把
 * 500 题那一档的预算直接撑爆（偏差 D5 的整个理由）。两个计数器是给测试钉上界用的，
 * 不是诊断装饰 —— Task 8 的查找上界断言全靠 `lookups`。
 */
internal class QuestionSimularity(questions: List<Question>) : Simularity {

    private val byId: Map<Long, Question> = questions.associateBy { it.id }
    private val grams = HashMap<Long, Set<String>>(questions.size)
    private val pairs = HashMap<Pair<Long, Long>, Float>(questions.size * 2)

    /** `sim()` 被调用的次数（含缓存命中）。约束算法的工作量口径。 */
    var lookups: Int = 0
        private set

    /** 真正落到 [TextSimilarity] 的次数（缓存未命中）。二元组缓存有效性的口径。 */
    var computations: Int = 0
        private set

    override fun sim(a: Long, b: Long): Float {
        lookups++
        if (a == b) return 1f
        val qa = byId[a] ?: return 0f
        val qb = byId[b] ?: return 0f
        val key = if (a < b) a to b else b to a
        pairs[key]?.let { return it }
        computations++
        val value = TextSimilarity.questionSimilarity(
            stemA = qa.stem, tagA = qa.conceptTag,
            stemB = qb.stem, tagB = qb.conceptTag,
        )
        pairs[key] = value
        return value
    }
}
```

> 上面那版**先别照抄**：`grams` 字段声明了却没被用到，而二元组按 id 缓存正是 `QuestionSimularityTest` 里「二元组按 id 缓存不在每次查表时重建」那条要保证的东西。实现时把 `TextSimilarity` 的调用换成走这份缓存：`dice(gramsOf(qa), gramsOf(qb))` 同考点时再 `maxOf(..., CONCEPT_FLOOR)`，`gramsOf(q)` 用 `grams.getOrPut(q.id) { TextSimilarity.bigrams(TextSimilarity.normalize(q.stem)) }`。
> 但**不要在 `TextSimilarity` 上新增一个吃 `Question` 的重载**把缓存下沉过去：`TextSimilarity` 那层的公开签名保持只吃字符串（Task 1 已钉），缓存属于提供方。为此把 `questionSimilarity(stemA, tagA, stemB, tagB)` 留作**不缓存的参考实现**，提供方自己组 `dice + 地板`。留一条测试钉两者对同一对输入给同一个值，免得两份算术各说一套：
>
> ```kotlin
> @Test fun `缓存路径与参考实现给同一个值`() {
>     val a = q(1, stem = "下列句子中没有语病的一项是", tag = "病句")
>     val b = q(2, stem = "下列句子中没有语病的一项是（　）", tag = "病句")
>     val s = QuestionSimularity(listOf(a, b))
>     assertEquals(TextSimilarity.questionSimilarity(a.stem, a.conceptTag, b.stem, b.conceptTag), s.sim(1L, 2L), 1e-6f)
> }
> ```
>
> 若嫌两条算术风险大，另一条路是让 `QuestionSimularity` 只在缓存命中失败时调 `TextSimilarity.questionSimilarity`，缓存的是**分值**而不是二元组（`pairs` 已经这么干）—— 那样 `grams` 整个字段删掉，重复计算只发生在**不同对**之间，每对不同对算一次本来就无法避免。**采用这条**：`pairs` 记忆化已经保证了「同一对至多算一次」，`grams` 是第二份缓存、买不到东西还多一个状态。所以：删 `grams`，`QuestionSimularityTest` 里那条 `至多 15 次真实计算` 的用例仍然成立（6 题的 15 个不同无序对，15 次计算是上限）。KDoc 相应改成「记忆化的粒度是**对**，不是单题的二元组：一条题只出现在一对里时，它的二元组只算一次」。

```kotlin
package com.studykit.ui.study

/**
 * 簇型相似度替身：同簇 0.9f（> 词面 tauHi 0.60 ⇒ 相邻违规），异簇 0f（< tauLo 0.15 ⇒ 可换位可当缓冲）。
 *
 * 用它而不是用真实词面打分，是因为这一层要钉的是**约束算法**而不是打分器：
 * 簇结构让"该不该分开"没有歧义，测试期望值能写成字面量。打分器另有 `TextSimilarityTest` 钉。
 */
internal class FixtureSim(private val cluster: Map<Long, Int>) : Simularity {
    var lookups: Int = 0
        private set

    override fun sim(a: Long, b: Long): Float {
        lookups++
        if (a == b) return 1f
        val ca = cluster[a] ?: return 0f
        val cb = cluster[b] ?: return 0f
        return if (ca == cb) 0.9f else 0f
    }
}

/** 造 n 条同簇/异簇混合的队列项：ids 从 [base] 递增，urgency 递减，簇按 [clusters] 轮着给 */
internal fun queueItems(base: Long, n: Int, clusters: List<Int>): List<QueueItem> =
    (0 until n).map { i ->
        QueueItem(
            id = base + i,
            urgency = (n - i).toFloat(),
            subject = "S${clusters[i % clusters.size]}",
        )
    }

/** 只改簇不改其它字段 */
internal fun List<QueueItem>.withCluster(clusterOf: (QueueItem) -> Int): List<QueueItem> =
    map { it.copy(subject = "C${clusterOf(it)}") }

internal fun clusterMap(items: List<QueueItem>, clusterOf: (QueueItem) -> Int): Map<Long, Int> =
    items.associate { it.id to clusterOf(it) }
```

```kotlin
package com.studykit.ui.study

import kotlin.math.abs

/** 队列里的一项。[urgency] 越大越该先出；装配层用它承载"原序位置"，见 `QuestionQueuePlanner`。 */
internal data class QueueItem(val id: Long, val urgency: Float, val subject: String)

/** 一对被判定为易混的对子，[gap] 是**最终**队列里两者的距离（不是移动前的） */
internal data class QueueDrill(val aId: Long, val bId: Long, val gap: Int)

/**
 * @param pulled 从缓冲池拉到前面的条数（受 [InterleavePolicy] 之外的 10% 上限约束）
 * @param maxAdjSim 最终队列里最相邻的一对相似度；**少于两条时为 null** ——
 *        null 表示"没得测"，不是"测出 0"。用 `Float?` 而不是拿 0f 当哨兵，
 *        因为 0f 会被下游读成"这些题一点都不像"，那是假信息。
 * @param unresolved 最终仍违反 `sim > tauHi` 的相邻位置下标（空 = 修干净了）
 */
internal data class QueuePlan(
    val queue: List<QueueItem>,
    val pulled: Int,
    val maxAdjSim: Float?,
    val drillPairs: List<QueueDrill>,
    val unresolved: List<Int>,
)

/**
 * 相似题交错的两遍约束（文档 §② L1230）。
 *
 * 第一遍：`sim > tauHi` 的两题不许相邻 —— 先在 [InterleavePolicy.lookahead] 窗口内找一条
 * 与左邻足够不像（`sim < tauLo`）的题**换位**，找不到再从缓冲池**插一张**（受条数一成上限）。
 * 第二遍：混淆带 `[drillLo, drillHi]` 内的对子强制同场并隔开 `gapLo..gapHi` 题（Task 4）。
 *
 * 与文档参考实现的差别全部记在计划的偏差 D5/D6，四条各钉了一条测试：
 *  1. 有界窗口 + 每轮 `2n+4` 步预算 + 最多 `maxRepairRounds` 轮，替掉最坏 O(n²) 的全尾扫描；
 *  2. drills 之后**复扫**一遍（参考实现挪完 b 就不管新邻居了）；
 *  3. `maxAdjSim` 用 `maxOfOrNull`，少于两条给 null，不抛；
 *  4. 一切遍历序定死：排序键 `(urgency desc, id asc)`，混淆映射按 id 升序走。
 *
 * 纯函数：不吃 Android、不吃 Room、不做 IO，相似度一律从注入的 [Simularity] 拿。
 */
internal object QueueBuilder {

    /** 缓冲拉前的条数上限的分母：文档 L1264「pulled 上限 = due 数 ×10%」 */
    private const val PULL_CAP_PERCENT = 10

    fun build(
        due: List<QueueItem>,
        sim: Simularity,
        pool: List<QueueItem>,
        confusable: Map<Long, List<Long>>,
        policy: InterleavePolicy,
    ): QueuePlan {
        val q = due.sortedWith(compareByDescending<QueueItem> { it.urgency }.thenBy { it.id }).toMutableList()
        val inQueue = q.mapTo(HashSet(q.size)) { it.id }
        val cap = due.size * PULL_CAP_PERCENT / 100
        var pulled = repairAdjacent(q, inQueue, sim, pool, policy, policy.maxRepairRounds, cap)
        return report(q, sim, pulled, emptyList(), policy)
    }

    /**
     * 相邻修复。返回拉入的缓冲卡数。
     *
     * 为什么是"多轮 + 每轮步数预算"而不是一趟扫到底：换位与插入都会改变 i-1 处的相邻关系
     * （把 j 换到 i+1，j 原来的左邻 q[j-1] 就接上了老 q[i+1]）。参考实现单趟走完就交差，
     * 修好的位置和弄坏的位置都只按运气处理。这里回退一格重查，同时用 `2n+4` 步预算和
     * `maxRepairRounds` 轮数封住上界 —— 上界存在，Task 8 才钉得住。
     */
    private fun repairAdjacent(
        q: MutableList<QueueItem>,
        inQueue: MutableSet<Long>,
        sim: Simularity,
        pool: List<QueueItem>,
        policy: InterleavePolicy,
        rounds: Int,
        pullCap: Int,
    ): Int {
        var pulled = 0
        for (round in 0 until rounds) {
            var changed = false
            var budget = q.size * 2 + 4
            var i = 0
            while (i < q.size - 1 && budget-- > 0) {
                if (sim.sim(q[i].id, q[i + 1].id) > policy.tauHi) {
                    val moved = swapInWindow(q, i, sim, policy) ||
                        (pulled < pullCap && insertBuffer(q, inQueue, i, sim, pool, policy).also { if (it) pulled++ })
                    if (moved) {
                        changed = true
                        i = (i - 1).coerceAtLeast(0)
                        continue
                    }
                }
                i++
            }
            if (!changed) break
        }
        return pulled
    }

    /** 把窗口内第一条"与 q[i] 足够不像"的题换到 i+1。返回是否动了 */
    private fun swapInWindow(q: MutableList<QueueItem>, i: Int, sim: Simularity, policy: InterleavePolicy): Boolean {
        val from = i + 2
        val to = minOf(i + 1 + policy.lookahead, q.lastIndex)
        for (j in from..to) {
            if (sim.sim(q[i].id, q[j].id) < policy.tauLo) {
                val t = q[j]
                q[j] = q[i + 1]
                q[i + 1] = t
                return true
            }
        }
        return false
    }

    /**
     * 从池里挑一条缓冲卡插到 i+1。候选必须**同时**与左右两邻足够不像 ——
     * 只查一侧会把一个违规换成两个（文档 L1246 两侧都查，这条照抄）。
     */
    private fun insertBuffer(
        q: MutableList<QueueItem>,
        inQueue: MutableSet<Long>,
        i: Int,
        sim: Simularity,
        pool: List<QueueItem>,
        policy: InterleavePolicy,
    ): Boolean {
        val buffer = pool.firstOrNull {
            it.id !in inQueue &&
                sim.sim(it.id, q[i].id) < policy.tauLo &&
                sim.sim(it.id, q[i + 1].id) < policy.tauLo
        } ?: return false
        q.add(i + 1, buffer)
        inQueue += buffer.id
        return true
    }

    /** 汇总最终队列的读数（第二遍与复扫都复用这一份，不再各算各的） */
    private fun report(
        q: List<QueueItem>,
        sim: Simularity,
        pulled: Int,
        drills: List<QueueDrill>,
        policy: InterleavePolicy,
    ): QueuePlan {
        val adjacent = (0 until q.lastIndex).map { i -> i to sim.sim(q[i].id, q[i + 1].id) }
        return QueuePlan(
            queue = q,
            pulled = pulled,
            maxAdjSim = adjacent.maxOfOrNull { it.second },
            drillPairs = drills,
            unresolved = adjacent.filter { it.second > policy.tauHi }.map { it.first },
        )
    }
}
```

```kotlin
import org.junit.Assert.assertEquals
import org.junit.Assert.assertTrue

class QueueBuilderDrillTest {

    private val p = LexicalInterleave.DEFAULT

    /**
     * 显式夹具：subject 相同 ⇒ 允许 drill；sim 由 score 直接给（不走簇）。
     * [score] 收到一对 id，返回分值。
     */
    private class ScoredSim(private val score: (Long, Long) -> Float) : Simularity {
        private val memo = HashMap<Pair<Long, Long>, Float>()
        var computations = 0
        override fun sim(a: Long, b: Long): Float {
            if (a == b) return 1f
            val key = if (a < b) a to b else b to a
            memo[key]?.let { return it }
            computations++
            return score(a, b).also { memo[key] = it }
        }
    }

    private fun drillItems(spec: List<Pair<Long, String>>) =
        spec.mapIndexed { idx, (id, subject) -> QueueItem(id, (spec.size - idx).toFloat(), subject) }

    private fun bandSim(vararg pairs: Triple<Long, Long, Float>) = ScoredSim { a, b ->
        pairs.firstOrNull { (it.first == a && it.second == b) || (it.first == b && it.second == a) }?.third ?: 0f
    }
```

```kotlin
    /** 移动条数的硬预算：每次移动要 `indexOfFirst`（O(n)），不设上限就退化成 O(n·k) */
    private const val DRILL_MOVE_BUDGET = 32

    /**
     * 第二遍：把混淆带里的对子强制同场、隔开 `gapLo..gapHi` 题。
     *
     * 遍历序全部定死（偏差 D6 第 4 条）：外层按 `aId` 升序（`TreeMap`），内层按伙伴 id 升序，
     * 并且只处理规范化方向（`bId > aId`）—— 对称写入的映射如果两侧都处理一遍，
     * 同一对会被挪两次，第二次的起点还是第一次的结果，队列就随插入序漂了。
     *
     * [QueueDrill.gap] 报的是**最终队列里的真实距离**，不是"打算挪成的距离"：挪不动的时候
     * 也要让调用方看得见它没挪成（见测试「挪不动时宁可不挪也不能造违规」）。
     */
    private fun applyDrills(
        q: MutableList<QueueItem>,
        sim: Simularity,
        confusable: Map<Long, List<Long>>,
        policy: InterleavePolicy,
    ): List<QueueDrill> {
        if (confusable.isEmpty()) return emptyList()
        val drills = ArrayList<QueueDrill>()
        var moves = 0
        for ((aId, partners) in java.util.TreeMap(confusable)) {
            for (bId in partners.sorted()) {
                if (bId <= aId) continue                      // 规范化方向：一对只处理一次
                if (moves >= DRILL_MOVE_BUDGET) break
                val ia = q.indexOfFirst { it.id == aId }
                if (ia < 0) continue
                val ib = q.indexOfFirst { it.id == bId }
                if (ib < 0) continue
                val gap = abs(ia - ib)
                if (gap in policy.gapLo..policy.gapHi) {
                    drills.add(QueueDrill(aId, bId, gap))     // 已经隔开了，不动也记：调用方要的是"这一场有成对出现"
                    continue
                }
                val moving = q.removeAt(ib)
                placeBeside(q, ia, ib, moving, sim, policy)
                moves++
                drills.add(QueueDrill(aId, bId, abs(q.indexOfFirst { it.id == aId } - q.indexOfFirst { it.id == bId })))
            }
        }
        return drills
    }

    /**
     * 把 [moving] 放到距 anchor [InterleavePolicy.gapLo] 题的位置。
     *
     * 先删后算：`removeAt(ib)` 会让 `ib` 之后的所有下标左移一格，anchor 在 `ib` 之后时必须减一
     * —— 文档参考实现正是漏了这一步（偏差 D6 第 1 条）。
     *
     * 落点两侧如果有 `sim > tauHi` 的邻居，**原位放回并放弃这次移动**：交错的目的就是把像的题
     * 分开，用制造新违规的方式消除旧违规是倒着走。放弃之后由复扫和 `unresolved` 处理。
     */
    private fun placeBeside(
        q: MutableList<QueueItem>,
        ia: Int,
        ib: Int,
        moving: QueueItem,
        sim: Simularity,
        policy: InterleavePolicy,
    ) {
        val anchor = if (ib < ia) ia - 1 else ia
        val target = (anchor + policy.gapLo).coerceIn(0, q.size)
        val clashes = (target > 0 && sim.sim(moving.id, q[target - 1].id) > policy.tauHi) ||
            (target < q.size && sim.sim(moving.id, q[target].id) > policy.tauHi)
        if (clashes) {
            q.add(ib, moving)                                 // 原位放回：长度与内容都不变
            return
        }
        q.add(target, moving)
    }

    /**
     * 混淆对映射：同科目、分值落在 `[drillLo, drillHi]`（**两端都含**，文档 L1230 写的就是闭区间）、
     * 每卡最多 [InterleavePolicy.topK] 个伙伴，并**对称写入**（文档 L1227）。
     *
     * 返回的 `Map` 键升序、每个 value 按 id 升序：调用方的确定性依赖这两条。
     * 对称补齐会让某个伙伴的清单变长，所以补齐后再按 `(分值降序, id 升序)` 重排并截回 topK ——
     * 截的是最不像的那些，不是按 id 硬砍。
     *
     * 成本：同科两两比对，O(同科条数²) 次查表。**生产路径喂的是 ≤20 条的会话池**，
     * 500 条那一档（Task 8）测的是 `build`，混淆映射按文档自己的做法当输入给定。
     * 真要给 500 条算混淆对，那正是语义包计划里 `confusable` 表存在的理由（文档 L1226）。
     */
    fun confusablePairs(
        items: List<QueueItem>,
        sim: Simularity,
        policy: InterleavePolicy,
    ): Map<Long, List<Long>> {
        val scored = HashMap<Long, MutableMap<Long, Float>>()
        for (a in items) {
            if (a.subject.isBlank()) continue                  // 没有学科归属就不参与"同学科"配对
            val partners = scored.getOrPut(a.id) { HashMap() }
            for (b in items) {
                if (b.id == a.id || b.subject != a.subject) continue
                val value = sim.sim(a.id, b.id)
                if (value in policy.drillLo..policy.drillHi) partners[b.id] = value
            }
        }
        val union = HashMap<Long, MutableSet<Long>>()
        for ((a, partners) in scored) {
            for (b in partners.keys) {
                union.getOrPut(a) { HashSet() }.add(b)
                union.getOrPut(b) { HashSet() }.add(a)         // 对称写
            }
        }
        val out = TreeMap<Long, List<Long>>()
        for ((a, partners) in union) {
            val ordered = partners
                .map { it to (scored[a]?.get(it) ?: sim.sim(a, it)) }
                .sortedWith(compareByDescending<Pair<Long, Float>> { it.second }.thenBy { it.first })
                .take(policy.topK)
                .map { it.first }
                .sorted()                                      // 最终按 id 升序：applyDrills 的遍历序
            out[a] = ordered
        }
        return out
    }
```

```kotlin
/**
 * 会话内提示该挂在哪几张题上：一个 drill 对子里**排在后面的那张**。
 *
 * 挂在前面那张没意义 —— 用户还没遇到伙伴，提示就成了剧透。
 * 队列里不存在的 id 直接忽略（缓冲卡拉进来的题不进混淆映射，但调用方可能传整份映射）。
 */
internal fun drillNoteIds(queue: List<QueueItem>, drills: List<QueueDrill>): Set<Long> {
    if (drills.isEmpty()) return emptySet()
    val position = HashMap<Long, Int>(queue.size)
    queue.forEachIndexed { i, item -> position.putIfAbsent(item.id, i) }
    val out = HashSet<Long>()
    for (drill in drills) {
        val pa = position[drill.aId] ?: continue
        val pb = position[drill.bId] ?: continue
        out += if (pa < pb) drill.bId else drill.aId
    }
    return out
}
```

```kotlin
package com.studykit.ui.study

import com.studykit.data.entity.Question

/**
 * 一轮题目队列的装配结果。
 *
 * @param questions 最终顺序的题（**与输入同一批实例**，不复制、不改字段）
 * @param pulled 从池里拉到前面的条数
 * @param maxAdjSim 语义遍没跑时为 null（回退链），跑了就是最终相邻最大值
 * @param drillIds 该挂「这两张卡容易混」提示的题 id（每个 drill 对子里靠后的那张）
 */
internal data class QuestionQueuePlan(
    val questions: List<Question>,
    val pulled: Int,
    val maxAdjSim: Float?,
    val drillIds: Set<Long>,
)

/**
 * 唯一一处把（设置 + 这一轮的题 + 候选池）拼成交错队列的地方。
 *
 * 两层叠在一起，上层不改下层：
 *  1. 学科层 —— [interleaveBySubject]，与 v2.x 起完全相同；关掉交错开关时它就是原序；
 *  2. 题面层 —— [QueueBuilder]，在第 1 层的**结果顺序**上做最小扰动。
 *
 * 第 2 层把原序编码成 `urgency = n - index`（越靠前越大），于是 `QueueBuilder` 的
 * "按 urgency 降序"初值就等于第 1 层给出的顺序：**没有相似题要分开时，输出逐元素等于输入**。
 * 这条不是巧合，是回退链能写成相等断言的前提（测试「语义遍开但题互不相像时输出与不开完全相同」）。
 * 换句话说：这一层只会在真的看到相似题时才动手，它不动手的时候必须看得见"什么都没变"。
 *
 * 候选池 [pool] 不参与学科层，只当缓冲卡来源；它里面的题**是用户这一轮新见到的**，
 * 所以 `QueueBuilder` 的 pull 上限（条数一成）是唯一的护栏 —— 见测试「池里的条数受一成上限」。
 */
internal fun planQuestionQueue(
    session: List<Question>,
    pool: List<Question>,
    interleaving: Boolean,
    semantic: Boolean,
    policy: InterleavePolicy = LexicalInterleave.DEFAULT,
): QuestionQueuePlan {
    val base = interleaveBySubject(session, enabled = interleaving)
    if (!semantic || base.size < 2) {
        return QuestionQueuePlan(questions = base, pulled = 0, maxAdjSim = null, drillIds = emptySet())
    }
    // 池里去掉与本轮重复的 id：同 id 出现两次会让 QueueBuilder 的 inQueue 判重失效
    val baseIds = base.mapTo(HashSet(base.size)) { it.id }
    val extra = pool.filter { it.id !in baseIds }
    val cards = (base + extra).associateBy { it.id }
    val sim = QuestionSimularity(base + extra)
    val items = base.mapIndexed { index, card ->
        QueueItem(id = card.id, urgency = (base.size - index).toFloat(), subject = card.subject)
    }
    val poolItems = extra.map { QueueItem(id = it.id, urgency = 0f, subject = it.subject) }
    val result = QueueBuilder.build(items, sim, poolItems, QueueBuilder.confusablePairs(items, sim, policy), policy)
    val ordered = result.queue.mapNotNull { cards[it.id] }
    check(ordered.size == result.queue.size) { "装配丢条目: 队列 ${result.queue.size} 题，映射回 ${ordered.size} 题" }
    return QuestionQueuePlan(
        questions = ordered,
        pulled = result.pulled,
        maxAdjSim = result.maxAdjSim,
        drillIds = drillNoteIds(result.queue, result.drillPairs),
    )
}

/**
 * 设置行「相似题打散」的说明。收进函数是为了钉进测试：
 * 文案一旦散落在 Composable 的字面量里，就没有任何机器在守着它不说假话（偏差 D2）。
 */
internal fun semanticInterleaveHint(): String =
    "把题面文字上就很像的题尽量隔开几道出；同一轮里已经出现的同一学科同考点题，会尽量隔三到五题再遇一次 —— " +
        "挪不开就照原样出。判据是题干文字与考点标签，不联网、不装额外东西。关掉这一层就只按学科打散。"

/** 会话内提示（文档 L1266 逐字）。它只解释"为什么隔开放"，不解释相似度是怎么算的。 */
internal fun confusableDrillTip(): String = "这两张卡容易混，隔开放是故意的。"
```

> 1. 原稿「考点标签相同的题会被**安排在同一轮里**」——**结构上就做不到**：`confusablePairs` 只喂会话内的题，

> 2. 原稿「别让它们连着出现」是无条件承诺，而 builder 在落点被拒或夹到队尾时**会**留下 `sim > tauHi` 的相邻

```kotlin
import org.junit.Assert.assertEquals
import org.junit.Assert.assertTrue
import org.junit.Test

class QueueBuilderStressTest {

    private val p = LexicalInterleave.DEFAULT

        /**
     * 500 题分 50 簇、每簇 10 题：簇内 0.9（违规）、簇间 0.0（可换）。urgency 递减。
     *
     * 簇号必须是 **`id / 10`（连号同簇）**，不能是 `id % 50`：后者让相邻 id 分属不同簇，
     * 于是初序里**一对违规都没有**，整条"压力测试"只测了"不崩"，
     * 换位项与插池项都停在 0（派发前手推发现，是计划自己的错）。
     * 按 `id / 10` 走，每 10 连号一簇 ⇒ 每簇内部 9 对相邻违规、共 450 对，
     * 而下一簇就在 1~10 格内 ⇒ 窗口找得到可换的（这才轮到 lookahead 说话）。
     */
    private fun fiveHundred(): Pair<List<QueueItem>, FixtureSim> {
        val items = (1L..500L).map { id -> QueueItem(id, (501 - id).toFloat(), subject = "C${id / 10}") }
        val cluster = items.associate { it.id to (it.id / 10).toInt() }
        return items to FixtureSim(cluster)
    }

    @Test fun `五百题空池构建的查找次数在闭式上界内`() {
        val (items, sim) = fiveHundred()
        val plan = QueueBuilder.build(items, sim, emptyList(), emptyMap(), p)
        // 上界住在 `QueueBuilder` 的类 KDoc 里（那里是唯一事实源，两处各写一份就是一份债）。
        // KDoc 是**五项**；本条夹具传 `confusable = emptyMap()`，所以其中两项为 0 ——
        // 这件事必须写在账上，否则读代码的人会以为下面三项就是全部上界：
        //  - 换位项：n × (lookahead + 1) × maxRepairRounds（每个位置 1 次相邻判定 + 窗口内至多 lookahead 次候选判定）
        //  - 复扫项：n × (lookahead + 1)，仅当 drills **真挪动过卡**才跑 ⇒ 空映射时为 0
        //  - 插池项：违反位置数 × maxRepairRounds × |pool| × 2 —— 空池时这一项为 0（firstOrNull 一次都不问）
        //  - drills 落点项：DRILL_MOVE_BUDGET × 2 ⇒ 空映射时为 0
        //  - 读数项：report 把每一对相邻读两遍（maxAdjSim 一遍、violates 一遍）⇒ 2 × (n - 1)
        // 注：T3 评审把「每轮 2n+4 步预算」连同换位后回退一格一起删了，所以原稿那个公式已经作废。
        val swapTerm = items.size * (p.lookahead + 1) * p.maxRepairRounds
        val poolTerm = 0
        val reportTerm = 2 * (items.size - 1)
        val bound = swapTerm + poolTerm + reportTerm
        assertTrue("lookups=${sim.lookups} 超上界 $bound", sim.lookups <= bound)
        assertEquals(items.size, plan.queue.size)
    }

        // 用簇型替身造不出"对所有邻居都不合格"的池卡（簇结构下相似是成片的），

        assertTrue(plan.unresolved.isNotEmpty())
```
