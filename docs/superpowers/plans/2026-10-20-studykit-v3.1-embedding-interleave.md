# StudyKit v3.1 语义交错（embedding 落地）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 把 v3.0 的**词面替身**换成真嵌入：题干 → bge-small-zh-v1.5 INT8 → 512 维向量 → 余弦相似度，驱动既有的交错队列；「意思相近但用词不同」第一次变得可见。

**Architecture:** 模型随包下发（assets，+23.9MB，MIT）；Kotlin 实现 BERT WordPiece 分词；ONNX Runtime Android（OCR 已在用的同一个运行时）跑前向；CLS 池化 + L2 归一化；`Simularity` 接缝上新增 `EmbeddingSimularity`，队列构建/策略/设置开关全部复用 v3.0-C 的既有结构。

**Spec:** 开发文档 §3「练习线 · 3.1 语义交错算法落地」与 §5「embedding 包（25MB）先于 LLM 包」；v3.0-C 计划里的 D3/D5/D10 与 `EmbeddingInterleave.DEFAULT` 的预留注释。

## 已核实的事实（2026-10-20，本机实测，不是转述）

| 项 | 值 |
|---|---|
| 模型来源 | ModelScope `Xenova/bge-small-zh-v1.5`（BAAI/bge-small-zh-v1.5 的 ONNX 转换） |
| 许可证 | **MIT**（BAAI README §License：可商用） |
| 文件 | `onnx/model_int8.onnx` **23,903,394 B**，sha256 `b9837c19ce154ff0726d398ee77abbc03a7faf0476c6f93016c84e531be7ebb5` |
| 词表 | `vocab.txt` **109,540 B**，sha256 `45bbac6b341c319adc98a532532882e91a9cefc0329aa57bac9ae761c27b291c`（21128 行） |
| 输入/输出 | `input_ids` / `attention_mask` / `token_type_ids` int64 `[1, seq]` → `last_hidden_state` `[1, seq, 512]` |
| 池化 | **CLS**（取 `last_hidden_state[0,0]`）+ L2 归一化（本机探针实测） |
| 分词 | BERT WordPiece：`do_lower_case=false`、`tokenize_chinese_chars=true`、标点单独切、`max 512` |
| 本机探针（Python ORT 1.31，CPU） | 同文 **1.0000**；仅标点差 **0.9571**；同考点换写法 **0.8120**；语义同义（速度变化越快 ↔ 加速度越大）**0.9271**；无关 **0.2809 / 0.3782** |

**分词金标准**（Kotlin 实现必须逐位复现；`maxlen=32` 补齐 `[PAD]=0`）：
```
"下列句子中没有语病的一项是"   => [101,678,1154,1368,2094,704,3766,3300,6427,4567,4638,671,7555,3221,102,0,…]
"设集合 A={x|x²<4}，求集合 A" => [101,6392,7415,1394,100,134,169,166,170,166,11699,133,125,171,8024,3724,7415,1394,100,102,0,…]
"velocity 变化越快"            => [101,12810,8897,10747,1359,1265,6632,2571,102,0,…]
```
（`100` = `[UNK]`，来自 `A`/`²` 这类词表外字符；这是正确行为，不许"修"成别的 id。）

### Task 1: 资产入库 + 分词器（纯层）

**Files:**
- Create: `app/src/main/assets/models/bge-small-zh-v1.5/model_int8.onnx`（23,903,394 B，从 `.qoder-tmp/bge/` 拷入，先核 sha256）
- Create: `app/src/main/assets/models/bge-small-zh-v1.5/vocab.txt`（109,540 B）
- Create: `app/src/main/assets/models/bge-small-zh-v1.5/PROVENANCE.md`（来源 URL、BAAI 原模型、MIT 许可证全文指针、两个 sha256、转换方 Xenova）
- Create: `app/src/main/java/com/studykit/ui/study/BertWordPieceTokenizer.kt`
- Test: `app/src/test/java/com/studykit/ui/study/BertWordPieceTokenizerTest.kt`

**Interfaces:**
- Produces: `internal class BertWordPieceTokenizer(vocabLines: List<String>)`、
  `fun encode(text: String, maxLength: Int = 64): IntArray`（含 `[CLS]`/`[SEP]`，超长截断，
  **不补 `[PAD]`**；金标准里末尾的 `0` 是 Python 探针补到 32 的，测试比到 `[SEP]` 为止的前缀）。
- 上游 `tokenizer.json` 实测：`BertNormalizer{clean_text=true, handle_chinese_chars=true, strip_accents=null, lowercase=false}`；
  `BertPreTokenizer`；`max_input_chars_per_word=100`（单词 >100 字符直接 `[UNK]`）；
  `clean_text` 去 `Cc` 控制字符（`\t`/`\n`/`\r` 留作空白）、`U+0000`、`U+FFFD`。
- 分词规则 **逐条**：CJK（`4E00–9FFF`、`3400–4DBF`）单独成 token；ASCII 标点（`!–/`、`:–@`、`[–\``、`{–~`）与 Unicode `P*` 类单独成 token；空白切断；其余连续非空白非标点为一词；
  WordPiece 贪心最长匹配（续片加 `##`），失败给 `[UNK]=100`；`[CLS]=101`、`[SEP]=102`、`[PAD]=0`。
- 测试：上面三条金标准逐位断言 + 一条"超长截断后仍以 `[SEP]` 结尾" + 一条空串只含 `[CLS][SEP]`。
