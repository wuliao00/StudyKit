# StudyKit 手写 baseline profile —— ART 文本 profile 语法（不是 R8 keep 语法！）
#
# 语法（见 docs/superpowers/specs/2026-09-18-studykit-v2-design.md §4）：
#   [HSP 标记]L<包/类描述符>;-><方法名>(<参数描述符>)<返回描述符>
#   [HSP 标记]L<包/类描述符>;->**(**)**          ← 该类全部方法
#   L<包/类描述符>;                              ← 只写类描述符＝该类整体进 profile
# H=hot、S=startup、P=post-startup；`**` 通配由 AGP 的 expand<Variant>ArtProfileWildcards
# 任务在编译期按真实类表展开，所以每条规则都必须能对上源码里存在的类。
# 反例（旧版本文件里的写法）：`Lcom/studykit/ui/theme/** { * }` 是 R8 keep 语法，
# profile 解析器读不懂，会**静默丢弃**——这正是本文件之前 13/17 行不生效的原因。
#
# 打包与验证：AGP 把本文件编成 ART 二进制 profile 打进 release APK 的
# assets/dexopt/baseline.prof*（profileinstaller 安装期写入系统），
# CI 的 release-build job 用 `unzip -l` 断言该文件确实存在，缺失即 fail。
#
# 覆盖面：启动链（Application / Activity / DI 容器 / Room）+ 主题与动效令牌层 +
# 底栏导航 + 四个 Tab 首帧与其高频组件 + 背单词热路径（翻面与滑动评价），共 55 条规则。
# 刻意**不含**录入页、详情页、日历与错题拍照等二级页面：规则越多安装期越慢，
# 而那些路径的收益要真机帧率数据才能确认（M1 由用户装 debug APK 反馈）。
# 类名核对口径：@Composable 顶层函数所在文件的类为「文件名 + Kt」，其组合 lambda 在
# `XxxKt$…` 里；object / class 则直接用类名（如 AppTheme、MotionSpec、Palette 均为 object）。
