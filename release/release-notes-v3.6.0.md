# StudyKit v3.6.0

> 版本号 `3.6.0 / 28`　·　发布日期 2026-10-30　·　Room 仍 v12（无迁移）

## 这一版做了什么

### OCR 的两个模型不再必须塞在 APK 里

检测模型 9.9 MB + 识别模型 21.2 MB，以前跟着 APK 走，每次升级都要重新下 31 MB。现在它们可以**按需下载**：

- 托管在 jsDelivr；识别模型超过单文件 20 MB 上限，切成三段（`models-host/ocr/rec.part1..3`），
  下载后顺序拼接；
- 逐段校验 + 拼接后整体再校验一次 sha256，**先写 `.tmp`、校验通过才 rename**——
  中断/被杀/校验失败时正式文件从未出现过，引擎不会把半截模型当成"已安装"；
- 下载中有字节级进度，失败把原因写回卡片；删除只删下载版，内置那份删不掉。

**设置 → OCR 模型** 是这个功能的唯一入口：每个模型显示 已内置 / 已下载 / 未下载 / 失败，
一键下载、一键删除。

引擎的读取顺序是 **下载版 → APK 内置版 → 报一句"去设置下载"**，识别过程仍然全程离线。

### 精简包：少 25.5 MB

把两个 `*_ppocrv6_small.onnx` 从 `app/src/main/assets/models/` 挪出去再 `assembleDebug`：

| | 大小 | 说明 |
| --- | --- | --- |
| 完整包 | 121,228,530 B | 模型内置，装完即可离线识别 |
| 精简包 | 94,262,870 B | 首次识别前需在设置里下载模型 |

（试过 `ignoreAssetsPattern` 与 `sourceSets.assets.exclude` 两条 Gradle 路线，都不改变产物大小，
所以用"挪文件再构建"这条最笨但可靠的路线，已写进 README。）

## 真机验证（vivo V2156A / Android 11）

1. 装精简包（3.6.0 / 28）→ 设置 → OCR 模型：两个都显示「未下载 · 9.5 / 20.3 MB」；
2. 点「下载模型」→ 进度条逐字节推进；检测 9.5 MB 先完成并 rename 成正式文件，识别模型分三段继续；
3. 两个都变成「已下载」，落盘文件与清单逐字节一致：
   - `det_ppocrv6_small.onnx` 9,929,594 B，sha256 `090f04ab…`；
   - `rec_ppocrv6_small.onnx` 21,234,383 B，sha256 `6f327246…`（与 APK 内置那份完全相同）；
4. 用一张**没有文字层的扫描版 PDF**（自制：ffmpeg 画的 1200×700 文字图 → img2pdf）走「选文件」导入，
   提示「扫描版 PDF：已用离线 OCR 识别 1 页，建议核对后再导入」，正文识别为
   `已知函数f(x)=x^2+1 / 求f(2) 的值。 / A.4 B.5 C.6 D.9`——下载下来的模型确实在跑。

## 已知限制

- 下载 30 MB 在网络差的环境下会慢（真机这段走热点，实测约 6 分钟）；卡片上还没有"建议 Wi-Fi"的提示。
- 模型没下载时，拍照录入会报「OCR 检测模型未安装。去「设置 → OCR 模型」下载…」，
  但目前只是错误文案，没有一键跳转到设置页。
- 仓库里同时存在 `modelpack/`（六种可选模型包的完整下载框架，`BuildConfig.MODEL_PACK_UI` 控制、默认关闭）
  与本次的 `data/ocr/`：两者职责重叠，后续应把 OCR 模型并入 modelpack 的统一清单，而不是各搞一套。
