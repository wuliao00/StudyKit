# StudyKit v3.7.0

> 版本号 3.7.0 / 29。Room 仍 v12，无迁移。
> 本版只改 OCR 拍照/相册录题链路，不碰词库、调度、题库数据与既有导入格式。

## 这一版做了什么

### 拍完先体检：糊、暗、过曝、反光、明显倾斜都会先提示

拍照/相册选完图后，先用纯 CPU 统计做一次 640 长边的质量体检：

- 模糊（拉普拉斯方差）、偏暗、过曝、反光、明显倾斜五类问题；
- 命中任一问题会弹窗，给「仍然识别」和「重拍 / 换一张」两个选择，不强制拦截；
- 深色主题截图、浅色截图、黑底白字这类「看起来异常其实正常」的输入有反例测试，不误报。

### 自动摆正：投影法找文字行角度，1° 以上才转

- 480 长边灰度缩略图上粗搜 2°、细搜 0.5°，估计文字行相对水平的夹角；
- 只在 1°~12° 之间反向旋转，避免无意义重采样；估计不可信时返回 0；
- 摆正角度会写进预览页提示（例如「已自动摆正 3.2°」）。

### 低置信度行二次识别

- rec 置信度低于 0.72 的行，检测框扩边 12%、放大 1.6~2 倍再识别一次（最多 8 行）；
- 择优规则收在一个纯函数里（空白不覆盖、同文本提分、显著更高才换、弱行稍高就换），单测钉住；
- 重试行数写进报告，预览页可以看到「二次识别 N 行」。

### 置信度路由：低置信度默认不进库

- 每行分数、照片质量、摆正角度、重试行数合成一份 OcrReport；
- 导入预览顶部常驻提示：照片问题 / 摆正角度 / 识别置信度 / 低置信度行数；
- 低置信度行**默认剔除**（勾选框不勾），并写明「核对后可勾回」，用户可逐行勾回再导入。

### 缺模型一键去设置

拍照识别时如果两个 OCR 模型没下载，不再只弹一句错误：弹窗给「去设置」按钮，
直接从学习页/题库页跳到设置；设置里也已写明「建议 Wi-Fi 下载」。

## 机检

- 新增/扩展：DeskewTest、PhotoQualityAnalyzerTest、OcrReportTest、PpOcrEngineSanityTest（二次识别择优）、
  QuestionPhotoImportTest（置信度路由）、OcrTextExtractorContractTest（质量体检坏输入）；

  其中 PhotoQualityRealImageTest 用 PIL 渲染的真实文字页做阈值校准（清晰/糊/暗/白/倾斜 3°/6°）。

## 真机验证（vivo V2156A / Android 11）

- **覆盖升级**：设备原为 3.6.0 / 28，debug 签名一致（证书 SHA-256 f86c8a85...），adb install -r 直接覆盖，
  不用卸载；升级后 versionCode=29 / versionName=3.7.0，数据仍在（单词 1165、待复习 2、已掌握 6）。
- **OCR 管线 androidTest**：OcrPipelineDeviceTest 四条用例按方法逐条执行 **4/4 通过**：
  - 清晰页 det+rec 识别成功（4.10s，文本含 StudyKit，report.meanScore > 0.30）；
  - 6 度倾斜页摆正角落在 4~8 度、摆正后仍能识别（3.81s）；
  - 模糊页在跑模型前判 BLURRY（0.18s）；暗图判 TOO_DARK（0.18s）。
  - 如实说明：一次性跑整个测试类会被 vivo fast_freezer 把测试进程冻结、instrumentation 挂住，
    属设备 vendor 行为；验收按方法执行，细节见 docs/evidence/v370-ocr-device.md。
- 设备安装器对未知来源 APK 有「安全守护」二次确认，与 App 无关。

## 已知限制

- 只做角度摆正，不做透视校正与弯曲书页展平；
- 仍是「一行一题」文本格式，没有版面模型做题目切分；
- 图片里的公式仍按普通文本处理（Word 原生公式走既有 OMML → LaTeX）；
- 低置信度只做到「入库前默认剔除」，题目表还没有持久化的 needsReview 列；
- 评测集是合成图 + 真机点测，还没有 300 张真实题目的 CER 回归；
- 未新增用户纠错日志（隐私上只应留在本地、默认不导出）。
